# 카페24 운영 전환 리허설

대상은 기존 AIFECT 서버다. 사용자 이미지·음원·MR·녹음은 R2에 유지한다. 이 폴더의 도구는 DNS나 로그인·결제 원장을 바꾸지 않는다.

1. 공식 Sites 소스에서 빌드한 서버를 `worker.mjs`로, 같은 커밋의 `drizzle/`을 같은 임시 폴더에 준비한다. `node check.mjs <임시폴더>`는 운영 비밀키 없이 인메모리 DB에 스키마를 재현하고 공개 API와 익명 접근 차단을 확인한다.
2. 승인된 운영 DB 스냅샷은 접근 권한이 제한된 서버 디렉터리에 직접 저장한다. Git이나 채팅을 거치지 않는다. `restore.py`는 SQLite 호환 SQL 덤프 전용이다. 원본을 고치거나 기존 DB를 덮어쓰지 않는다. 무결성·외래 키 검사와 전체 테이블의 행 수·내용 검증용 HMAC을 만든다. 운영 호스트에서는 신뢰한 백업만 전용 비특권 사용자로 복원한다. 매니페스트는 비공개 파일로 보관하며 키는 별도 저장한다.
3. 쓰기를 멈추기 전에 서비스·작업자·예약 작업·콜백의 유입 경로, 로그인 키, R2 권한과 미디어 전송, 되돌릴 기준을 검증한다. 원본과 신규 DB 간 대조는 같은 시점의 매니페스트로만 한다. 다른 두 시점의 잔액을 비교해서 전환하지 않는다.
4. 복원 검사가 성공해도 DNS나 주 DB가 자동 전환되지는 않는다. 새 DB가 쓰기를 받기 시작한 뒤에는 변경분을 재동기화하지 않고 이전 D1로 돌리지 않는다.

Linux에서 `umask 077` 상태로 `python3 restore.py backup.sql new.sqlite --key-file verify.key >manifest.json`으로 실행한다. 같은 시점의 검증된 매니페스트가 있을 때만 `--compare trusted-manifest.json`을 사용한다. 이 파일들은 버전 관리 대상이 아니다.

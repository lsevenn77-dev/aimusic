# 더빙 녹음 흐름 개선

- 새 대본·음향 계획에서 ‘발소리 들려요?’와 같은 반응 대사에 연결된 효과음은 대사 전에 끝나도록 배치한다. 이미 생성된 오디오·제출된 목소리는 소급 변경하지 않는다.
- 녹음 준비 구간은 실제 생성된 음향 계획의 효과음 시작부터 재생한다. 대사 직전 3, 2, 1을 표시하며 준비 구간은 마이크 녹음 파일과 대사 타이머에 포함하지 않는다.
- 내 대사의 로컬 녹음은 대사별 Map에 유지한다. 대사 이동·재녹음에서 확인 창을 띄우지 않고, 화면 이탈 시 미저장 녹음 경고는 유지한다.
- 임시 저장 한 번으로 미저장 대사를 순서대로 업로드한다. 기존 서버의 배역 권한·revision·take ID 중복 방지 검증을 그대로 사용한다. 중간 실패 시 완료된 저장은 유지하고 남은 녹음과 요청 ID를 보존한다.
- 체크는 녹음한 내 대사에만 표시한다. ‘미녹음’, ‘녹음됨 · 저장 전’, ‘임시 저장됨’을 구분한다. 서버에 모든 대사를 저장한 뒤에만 제출할 수 있다.

## 검증

로컬 SQLite/R2 fixture와 합성 마이크로 두 대사 녹음 → 확인 창 없이 대사 이동 → 한 번의 임시 저장 → 새로고침 후 두 체크 유지까지 브라우저에서 확인했다. 단위 테스트는 준비 구간 PCM 제외, 녹음 경계, 권한 거절·정리, 다중 저장·중간 실패 후 재시도, 효과음 전주와 고정된 대사 시각을 검증한다.

PC 1440×900, 모바일 390×844에서 화면을 확인하고 320px·768px 가로 넘침과 버튼 크기를 확인했다. 실제 Android/iOS 마이크·블루투스와 새 유료 음향 생성은 이번 작업에서 검증하지 않았다. 저장 전 녹음은 해당 화면 메모리에 있으므로 임시 저장 전에 페이지를 닫으면 유실될 수 있다.

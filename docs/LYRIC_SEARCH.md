# 가사 기반 검색 운영

이번 기능은 외부 API나 모델 없이 Workers 안에서 실행한다. 기존 Gemini 음원 분류와는 별개이며 해당 기능이나 사용자 메타데이터를 변경하지 않는다. UI 및 원본 가사에는 변경이 없다.

## 분석과 검색

- `shared/lyric-semantics.js`: 한국어 규칙, 제한된 영어 표현, 정규화, 공통 동의어 사전. 문장을 분석하고 명시적 부정·반어 표현을 억제한다. 앞뒤 문장은 상황 및 위로/과거 이별 문맥의 근거에 사용한다. 반복 보너스는 제한된다.
- 신뢰도는 규칙 근거 점수이며 통계적으로 보정된 확률이 아니다. 단독 명사(예: 사랑)만으로는 분류하지 않는다. 주제 상위 3개가 주요 태그이고 나머지는 보조 태그다. 가사의 분위기와 실제 음원의 사운드는 구분한다.
- 원곡 가사는 `tracks.lyrics`(LRC 포함), 커버의 가사는 기존 감상 페이지처럼 원곡에서 가져온다. 원본을 변경하지 않고 분석용 복사본에서 시간·구간 표기를 제거한다.
- 5개 보조 테이블에 작업 상태·SHA-256·분석 버전·분석 시점·근거 규칙과 행 번호·태그·키워드·운영자 고정을 저장한다. 동의어 문자열은 곡마다 복제하지 않는다. 원문을 결과/로그에 저장하거나 검색 응답에 추가하지 않는다.
- `song-search.js`의 공통 범위가 `/api/catalog`(홈/발견) 및 `/api/search`(통합검색)에 적용된다. 제목 정확 일치 → 아티스트/창작자 정확 일치 → 제목 부분 일치가 먼저이며, 나머지 결과는 충족한 검색 의도 수·신뢰도·주요 태그·기존 관련도로 정렬한다. 기존 장르·태그·초성·오타 보정도 유지한다.
- 공개/차단/장르/분위기 범위 안에서만 후보를 찾는다. SQL 매개변수를 사용하고 검색 의도는 최대 12개, 키워드는 최대 6개다. `lyric_tags_lookup`/`lyric_terms_lookup` B-tree 역색인을 이용한다. 한국어는 공백 정규화와 구문 사전, 제한된 조사 제거로 처리하며 검색 시 원문을 분석하지 않는다.

## 큐와 복구

`0091_naive_starfox.sql`은 테이블·인덱스·등록/가사변경 트리거만 추가한다. 기존 레코드 일괄 변경은 migration에서 실행하지 않는다. 트리거는 작업 등록만 수행하며 실제 분석은 `waitUntil`에서 실행한다. 원곡 수정은 커버도 재등록한다.

초기 목록은 ID 커서로 32곡씩 등록하며 중단 후 이어진다. 버전 변경은 커서를 다시 순회한다. 기본 4곡, 설정 최대 8곡, 배치 시간 예산 1.8초, DB lease 45초, 요청 사이 2초 간격으로 제한한다. `LYRIC_ANALYSIS_BATCH_SIZE`로 축소 가능하고 `LYRIC_ANALYSIS_DISABLED=true`는 요청 기반 실행을 중지한다. 기존 API/내부 worker heartbeat 및 scheduled handler가 큐를 처리한다. 별도 cron 등록은 하지 않으므로 트래픽과 기존 worker가 모두 멈춘 동안에는 다음 실행까지 대기한다.

가사 SHA-256과 버전이 같으면 재분석하지 않는다. 동시 수정은 lease를 취소해 오래된 결과 저장을 막는다. 실패는 30/60초 후 재시도하고 3회 실패 또는 세 번째 처리 중 중단된 작업은 failed로 남긴다. 분석 실패는 업로드 응답을 기다리게 하지 않는다.

관리자 인증 및 기존 CSRF 처리를 거치는 `/api/admin/lyric-analysis`:

- GET: 전체 대상/완료/누락, 상태별 수, 최근 배치 시간, 분석 평균·최대 시간.
- POST `{"action":"run"}`: 제한된 1개 배치.
- POST `{"action":"retry_failed"}`: 실패한 작업만 재등록.
- POST `{"action":"rebuild"}`: 모든 파생 인덱스를 재분석해 복구. 원본·운영자 고정 유지.
- POST `{"action":"pin","track_id":"실제 곡 ID","tag_id":"hope","mode":"include"}`: 운영자 태그 고정. `exclude`는 제외, `clear`는 고정 해제. 고정 변경은 감사 기록과 함께 저장한다. 가사가 없어도 운영자가 명시적으로 지정한 태그는 유지하되 자동 태그는 만들지 않는다.

기존 관리자 MCP 통계의 `lyric_analysis`도 동일 집계를 제공한다. `done`은 가사가 있는 처리 완료, `no_lyrics`는 유효 가사가 없어 자동 태그를 만들지 않은 처리 완료다. `coverage.current==coverage.total` 및 missing=0, failed/queued/processing=0으로 완주를 확인한다.

## 검증과 한계

단위 테스트는 혼합 감정·단문·무가사·부정·명시적 반어·한국어/영어·자연어 검색을 검증한다. 실제 SQL fixture로 등록/수정/해시/경합/실패 재시도/고정/인덱스 재구축/원곡 상속/권한/검색 순위/페이지네이션을 검증한다. 배포 전 `npm run release:prepare`와 `npm run release:check`, 이후 `npm run release:verify`를 실행한다.

임의의 은유·복잡한 반어·이중부정·미등록 방언·한국어 형태소 전체를 이해하는 모델은 아니다. 애매한 가사는 태그가 적거나 없을 수 있다. 실제 운영 가사에 대한 사람의 정답 라벨 평가와 사전 확장을 후속으로 수행할 수 있다. 시간 지표는 wall time이며 Workers CPU·RSS 측정치가 아니다. 서버 설정의 CPU 한도나 운영 동시접속 부하를 추정하지 않는다.

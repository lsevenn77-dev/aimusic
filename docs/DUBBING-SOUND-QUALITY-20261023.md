# 더빙 음향 무음 결제 방지 / 장면 BGM

기준 소스: Sites 197 후보(6e224d265073b7d961f9ce7091b46635c7c76cd5), 현재 배포 확인: 196.

- 장면 BGM의 3개/20%/24초/용도별 길이 제한과 중간 음악 삭제를 제거한다. 기존 전체 24 cue, 작품 5분, 공급자 파일 길이 제한은 유지한다.
- 슬픔·상실·재회·긴장 등 장면 감정에 맞게 음악을 작성한다. 새 AI 음향 요청은 가능하면 저장된 옛 제한 계획을 재사용하지 않고 현재 감독 지침으로 구성한다. 기존 대본/녹음/완료 음원은 변경하지 않는다.
- 음향 계획이 없거나 볼륨이 0, 파일 목록 누락, 실제 사용 구간 무음, 무음 합성이면 성공으로 확정하지 않는다. 실패 시 기존 원장 환급 경로로 원래 골드를 한 번만 복원한다.
- 음향 합성기는 각 cue의 실제 잘라 쓰는 구간을 디코딩하여 검증하고 `audibleCueCount`를 완료 API에 보낸다. 서버는 완료된 공급자 파일 목록과 이 수치, 최종 peak를 검증한 뒤에만 `fulfilled`로 전환한다.

## 배포 순서와 검증

이 후보는 웹 Worker와 `transcoder/dubbing.py`가 함께 필요한 변경이다. 운영 게시에는 사용자 승인이 필요하다. D1 migration은 없다.

1. 기존 합성 서버에 같은 후보의 `transcoder/dubbing.py`를 적용하고 음향 큐 프로세스만 재시작한다. 기존 음악 변환/최종 녹음 프로세스와 환경 비밀값은 보존한다. 새 메타데이터는 구버전 API에서도 무시하므로 합성 서버를 먼저 갱신한다.
2. 공식 Sites에 저장된 후보를 승인 후 게시한다. 신규 완료에는 `audibleCueCount`가 필수다. 구 합성기를 먼저 갱신하지 않으면 신규 제작이 검증 실패로 환급되므로 준비 없이 웹만 게시하지 않는다.
3. API 및 합성기 상태를 확인하고 승인된 실제 생성 1건을 청취한다. 로컬 검증은 합성 신호·모의 API로 실행하며 Pika/OpenAI에 유료 요청을 보내지 않는다. 장면에 맞는 음악인지 최종 청취 평가는 별도다.
4. 기존 무음 완료 건은 작품/제작 ID와 결제 기록을 확인한 뒤 개별 보상한다. 일괄 골드 지급이나 기존 오디오 삭제는 하지 않는다.

오류 시 새 음향 요청을 중단하고 이전 승인 버전으로 복원한다. 지급/차감/감사 기록은 삭제하지 않는다.

# AIFECT 디자인 시스템 규정 v1.0

**기준 페이지:** https://aifect.co.kr/#home  
**기준일:** 2026-10-23  
**적용 대상:** PC 웹, 모바일 웹, 추후 앱의 홈·PLAY·커뮤니티·메시지·마이·선물함·스튜디오·공통 팝업  
**우선순위:** (1) 현행 운영 코드/실제 홈 UI → (2) 사용자 승인 최종 화면 → (3) 이 규정의 확정 원칙 → (4) 추정 기준

> **검증 상태:** 공개 홈에서 서비스 구성과 메뉴 텍스트는 조회되었지만, 이 문서를 작성하는 환경에서는 실제 로그인 UI의 computed CSS를 추출하거나 브라우저 스크린샷을 캡처하지 못했다. 아래 수치 중 **확정** 항목은 사용자가 과거에 고정한 값이며, **시안 승인값**은 특정 컴포넌트에 한정된 레퍼런스다. 이들을 실제 운영 CSS에서 측정한 값으로 오인하지 마라. 코덱스가 실제 저장소/브라우저 접근 시 반드시 `scripts/audit-aifect-ui.mjs`로 검증 후 `reference/VERIFIED_SITE_TOKENS.md`를 작성하도록 한다.

## 1. 디자인의 정체성

**어두운 배경 위에서 콘텐츠가 먼저 보이는, 정돈되고 기능적인 음악 플랫폼.**

- 딥 네이비·차콜을 기본 표면으로 한다. 배경과 패널의 명도 차이는 부드럽게 처리한다.
- 핑크·라벤더·민트는 강조/활성 상태에만 절제해서 사용한다. 모든 요소에 포인트 컬러를 칠하지 않는다.
- 텍스트와 조작부의 정렬·일관성·가독성이 그라데이션/빛 효과보다 우선이다.
- **토스처럼 정돈된 UX**를 참고하되 토스의 밝은 배경이나 새 컴포넌트 스타일로 AIFECT를 갈아엎지 않는다.
- 콘텐츠 썸네일, 사용자의 사진, 실제 앨범 아트를 주요 시각 요소로 사용한다. 장식용 거대한 히어로 배너/배경 일러스트는 금지한다.

## 2. 색상 및 디자인 토큰: 확정/참고/미검증 구분

| 토큰 | 값 | 상태 | 적용 규칙 |
|---|---|---|---|
| Accent Mint | `#8EDDD2` | **사용자 확정** | 민트 포인트·상태. 다른 녹색/연두로 대체하지 않는다 |
| Approved Gradient CTA Example | `linear-gradient(100deg, #DCC6FF 0%, #BFCBF7 52%, #B8F1E3 100%)` | **프로필 팝업 승인 예시 (근사)** | 팔로우/프로필 수정 등 같은 계열의 주 CTA에만. 홈 실제 CTA의 CSS가 있으면 그 값을 우선 |
| Secondary Button Surface Example | `#1E2535` | **프로필 팝업 승인 예시** | 이미 같은 보조 버튼을 구현한 경우 참고. 전역 강제 적용 금지 |
| Secondary Button Border Example | `#2D364A` | **프로필 팝업 승인 예시** | 위와 동일 |
| Primary Pink | **사이트 CSS에서 읽을 것** | 미검증 | 임의 `#FF4FA3`, `#FF69B4` 등으로 고정하지 않는다 |
| Page / Sidebar / Surface | **사이트 CSS에서 읽을 것** | 미검증 | dark navy / charcoal, 현재 레이어 구분 유지 |
| Main Text / Muted Text | **사이트 CSS에서 읽을 것** | 미검증 | 흰색 계열/회색 계열. 연두색 텍스트 신규 사용 금지 |
| Borders / Dividers | **사이트 CSS에서 읽을 것** | 미검증 | 얇고 차분한 경계, 강조색 테두리 남발 금지 |

**색상 사용 우선순위:** 토큰 참조 → 기존 공통 컴포넌트 클래스 참조 → 같은 화면의 현행 CSS 참조 → 정말 필요할 때만 국소적인 새 토큰 제안. 새 HEX를 추가하는 경우 그 이유와 비교 이미지를 작업 보고에 쓴다.

**규칙:** 단순 강조를 위해 네온 발광, 강한 외곽 그림자, 다수의 무지개 그라데이션을 새로 만들지 않는다. 골드/실버 선물 재화 아이콘 색은 해당 기존 자산을 사용한다.

## 3. 타이포그래피

- 실제 홈에서 로딩하는 폰트 패밀리와 폰트 굵기를 확인 후 동일하게 사용한다. 새 폰트 설치 및 무단 교체 금지.
- 페이지 제목, 섹션 제목, 카드 제목, 본문, 캡션, 입력값의 **현재 사이트 typographic scale**을 샘플링해 토큰화한다.
- 한 화면 안에서 같은 계층의 제목은 같은 굵기·크기·행간이어야 한다. 아이콘과 텍스트는 중앙선 정렬.
- 보조 정보는 회색 계열. 밝은 연두/연녹색 텍스트는 신규 사용하지 않는다.
- 긴 곡명/크루명은 말줄임; 정보가 잘린 경우 접근 가능한 제목/툴팁 제공. 임의로 줄바꿈하거나 닉네임 글자 크기를 변형하지 않는다.

## 4. 간격, 모서리, 표면

- **현재 공통 `gap`, `padding`, `border-radius`, `shadow`, `border` 값 추출이 먼저.** 임의 숫자로 새 사이즈 체계를 덮어쓰지 않는다.
- 코드에 공통 간격 토큰이 없다면 4px 리듬(4/8/12/16/24/32)을 **제안 출발점**으로만 사용하고 실제 홈 카드 밀도와 비교해 확정한다.
- 얇은 구분선과 편안한 여백으로 섹션을 구분한다. 각 섹션을 별도의 무거운 박스/큰 그림자로 둘러싸지 않는다.
- PC의 현재 사이드바와 하단 미니플레이어 높이·너비·고정 상태를 절대 바꾸지 않는다.
- 새 카드의 모서리와 이미지 크롭은 같은 위치의 기존 콘텐츠 카드와 동일하게 한다.

## 5. 버튼, 탭, 아이콘

- **Primary CTA:** 같은 기능의 기존 컴포넌트 재사용. 승인된 프로필 팝업 계열에서는 라벤더→민트 소프트 그라데이션, 텍스트·아이콘은 진한 네이비.
- **Secondary CTA:** 사이트 기존 보조 버튼(어두운 면·얇은 회청색 선·밝은 글자). 단색 핫핑크 CTA를 새로운 기본값으로 도입하지 않는다.
- **Danger:** 강퇴·삭제 등 실질적 파괴 동작에만 제한적 표시, 재확인 필요.
- **Tabs / Segmented:** 활성 탭의 상태는 배경/글자색 변화로 즉시 구별; 비활성 탭은 차분한 회색. 선택 테두리나 굵기 남발 금지. 같은 화면의 탭 높이/간격 동일.
- **Icons:** 현행 아이콘 라이브러리의 정확한 아이콘과 stroke를 재사용; 이모지 대용, 혼합 아이콘 세트, 크기 들쭉날쭉 금지. 통상 16/20/24px 같은 기존 단계로 통일(수치는 실제 앱 확인 필요).
- **글로벌 메뉴 용어:** `홈`(집), `플레이`(삼각형 재생), `스튜디오`(기존 확정 아이콘). 사이드바의 그 외 메뉴 및 배치는 유지.
- 선택/hover/focus/disabled/loading의 상태 디자인은 새로 발명하지 말고 현재 앱 패턴과 맞춘다.

## 6. 카드 / 음악 콘텐츠 규칙

- 카드 썸네일 위에는 기존 **재생 버튼**을 그대로 유지한다. 새 재생 아이콘으로 중복하지 않는다.
- 완료 커버의 유형 `솔로 / 듀엣 / 더빙` 아이콘은 **썸네일이 아니라 곡 제목의 왼쪽**에 붙인다.
- 작품/가수/크루 사진은 실제 사용자·원곡·프로젝트 자산을 우선, 가상의 생성 이미지로 대체 금지.
- 카드 정보의 우선순위: **이미지 → 제목 → 창작자 → 필요한 통계/상태**. 모든 카드에 여러 배지와 버튼을 붙이지 않는다.
- `홈`은 제작곡·원곡 감상 영역; `PLAY → 둘러보기`는 완성 솔로·듀엣·더빙을 찾는 영역. 곡 이야기의 관련 커버 연결 유지.

## 7. 팝업·바텀시트

- PC 팝업은 현재 사이트에서 쓰는 작은 중앙 모달과 컴팩트한 헤더·컨트롤을 우선한다.
- 모바일은 필요한 경우 고정 높이 하단 시트. **기능 없는 긴 타원형 드래그 바를 표시하지 않는다.** 실제 드래그 확장 기능이 있는 경우에만 별도 승인받는다.
- 불필요한 설명문, ‘상단 장식 바’, 묵직한 그림자와 과도한 입체 테두리를 만들지 않는다.
- 닫기(X), 바깥 클릭/탭, ESC, 키보드 포커스, 안전 영역(safe area), 스크롤 고정 동작을 점검한다.
- 선물 팝업 승인 구조는 `docs/AIFECT_PAGE_LOCKS.md` 참조. 상품 목록만 스크롤하고 헤더·하단 컨트롤은 고정한다.

## 8. 반응형 규정

| 구간 | 행동 원칙 |
|---|---|
| Desktop (`1440×900` 기준 QA) | 실제 PC 사이드바/상단바/하단 재생바 고정; 기존 메인 콘텐츠 너비, 카드열·정보 밀도 참조 |
| Tablet (`768px` QA) | 기존 분기점 우선, 카드/팝업/탭이 잘리지 않는지 확인 |
| Mobile (`390×844` 기준 QA) | 고정 5탭 `홈 · 커뮤니티 · 플레이 · 메시지 · 마이`; 터치 우선·배너 최소화; 콘텐츠 카드 기본 2열(크루·토킹룸 목록) |
| Small Mobile (`320px` QA) | 결제/선물/닫기 등 필수 버튼 노출; 의도하지 않은 가로 스크롤 금지 |

- 모바일 조작 목표 44px 내외 터치 영역(접근성 권장); 정확한 비주얼 높이는 기존 앱 컴포넌트와 정합성 우선.
- 스마트폰 폭 전체에 큰 배너와 덩치 큰 버튼을 불필요하게 새로 넣지 않는다.
- PC CSS를 단순 축소해서 모바일에 쓰지 말고 현재 AIFECT 반응형 레이아웃을 조사한 후 대응.

## 9. 절대 금지 목록

1. 사용자가 지우라고 한 버튼·장식·카드를 다시 생성하기.
2. 사용자 요청 없이 메뉴 순서, 전역 색, 사이드바 선택 상태, 아이콘, 미니플레이어 변경하기.
3. 오래된 시안의 대형 네온 핑크 버튼, 글로우, 유리 질감 효과, 큰 둥근 팝업을 사이트 전역에 복제하기.
4. 임의 이미지·임의 수치·임의 선물 가격/이용자 데이터를 실제 화면의 값인 것처럼 적용하기.
5. 기존 기능이 있는데 별도의 데모 UI와 가짜 데이터층을 본 화면 위에 얹기.
6. 디자인만 요청받았는데 정산·후원·토킹룸 WebRTC·결제·계정 권한 로직 수정하기.
7. 배포·DB 변경·실제 선물 발송을 사용자 승인 없이 수행하기.

## 11. 자동 실측 도구

`scripts/audit-aifect-ui.mjs`은 Playwright가 설치된 실제 개발 컴퓨터에서 URL을 열어 **실제 computed style**을 JSON으로 저장하고 공개 페이지 PC·모바일 스크린샷을 캡처한다. 운영 사이트 접근이 제한되면 같은 스크립트를 로컬 실행 서버에 사용한다. 결과는 기본적으로 `audit-output/`에만 저장하고 별도 검토 없이 디자인 토큰을 자동 교체하지 않는다. 실행 가이드: `docs/AIFECT_STYLE_AUDIT.md`.

# 토크룸 앱 개선을 위한 서버 변경

기준: Sites 228 / `7a47802cc6972766e156b26559953eb1ef9ffcbf`. 기존 PLAY·커뮤니티·상점·인벤토리 변경을 유지한다. 앱 2.5.67(80)의 토크룸 변경과 함께 사용한다.

## 변경

- `seating_mode`: `approval`(허락 후 착석) / `free`(자유 착석). 기존 방과 필드가 없는 요청은 허락 후 착석을 유지한다.
- 방장만 방 설정을 변경한다. 자유 착석도 기존 8석 제한, 방장 고정 좌석, 중복 착석 방지, 강제 마이크 제한, 세션 세대 검증을 그대로 적용한다.
- 자유 착석은 비어 있는 좌석을 서버에서 원자적으로 확보하고 음소거 상태로 앉는다. 마이크를 자동으로 켜지 않는다. 새 좌석 상태는 모든 참여자에게 알린다.
- 자유 착석으로 바꾸면 대기 신청을 해제한다. 다른 회원을 자동으로 이동시키지 않는다. 기존 웹 클라이언트의 관련 없는 설정 저장은 현재 좌석 방식을 유지한다.
- Site의 방 생성 API가 음성 Worker에 좌석 방식을 전달한다. 방 설정은 기존 인증된 전달 경로를 사용한다.
- SQL migration 없음. 기존 Durable Object의 방 설정에 선택 필드만 저장한다. 운영 데이터/골드/선물 원장은 변경하지 않는다.

## 검증

- `node --test tests/voice-rooms.test.mjs tests/voice-final.test.mjs`: 44개 통과.
- `npm run release:prepare`: 전체 900개 중 898개 통과, 2개 기존 건너뜀, 실패 0.
- `npx wrangler deploy --dry-run --config realtime/wrangler.jsonc`: 기존 `aifect-voice-rooms` Worker 번들 생성 성공. 실제 배포는 실행하지 않았다.
- 동시 좌석 신청 충돌, 방장 권한, 음소거 착석, 전체 상태 알림, 마이크 제한, 상태 재로딩, 허락 후 착석 복귀를 검증했다.
- 기존 다이아 동시 요청 테스트가 첫 Promise만 201일 것으로 가정해 간헐적으로 실패했다. 결과 순서와 관계없이 200/201 한 쌍과 동일 영수증을 검증하도록 테스트만 수정했다. 결제/정산 코드는 수정하지 않았다.

## 운영 반영 순서

승인된 동일 소스 커밋의 별도 `aifect-voice-rooms` Worker를 먼저 업데이트하고 Site 후보 버전을 배포한다. Sites 배포만으로 별도 음성 Worker 코드가 갱신되지 않는다. 기존 Worker 계정·이름·DO/D1 바인딩을 유지하며 새 migration을 실행하지 않는다. 운영 중 방 연결 영향과 실제 두 기기 음성 품질은 별도 실기기 확인이 필요하다.

이 문서와 준비된 후보는 배포 승인 자체가 아니다. 실제 후보 버전·커밋에 대한 사용자 승인 후에만 운영 반영한다.

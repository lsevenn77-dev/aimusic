# AIFECT Android UI/UX 구현 지시서

작성일: 2026-10-18
대상: 기존 AIFECT 안드로이드 앱
승인된 시각 참고: `approved-streaming-first.png` (스트리밍을 강화한 두 번째 5화면 시안)
상태: 디자인 방향 승인 및 구현 전달 자료. 아직 저장소 확인, 코드 수정, 빌드, Git 업로드, 배포를 수행한 문서는 아니다.

## 1. 최우선 목표

AIFECT는 음악을 쉽게 듣고, 직접 부르고, 다른 사람과 교류하는 음악 서비스다.
이번 변경의 최우선 목표는 **스트리밍만 사용하는 사람도 편리한 앱**이다.
사용자가 명시적으로 유지·강화하도록 요청한 기능은 다음과 같다.

- 홈의 추천 · 차트 · 최신곡 · 발견.
- 내 음악 목록, 좋아요한 노래, 플레이리스트, 최근 감상으로의 쉬운 접근.
- 커버·듀엣·커뮤니티·메시지는 유지하되 감상 동선을 방해하지 않는 배치.
- 예쁜 화면뿐 아니라 실제 기능 연결, 편한 탐색, 작업·재생 상태 보존.

시안의 색감·레이아웃·정보 구성을 구현 참고로 사용한다. 시안은 앱 화면을 한 장으로 합친 콘셉트 보드이며 픽셀 단위의 완성 명세가 아니다. 휴대전화 테두리, 보드 제목, 설명 패널을 실제 앱 안에 구현하지 않는다.

## 2. 작업을 시작하기 전에 확인할 것

실제 저장소를 먼저 읽고 프레임워크, 안드로이드 앱 진입점, 화면 경로, 재생 상태 관리, 기존 디자인 토큰, 녹음 관련 최근 변경을 확인한다. 기술 스택이나 파일명을 추측하지 않는다.

현재 브랜치, 미커밋 변경, 다른 작업자의 변경을 확인한다. 사용자 작업을 덮어쓰거나 자동 초기화하지 않는다. 프로젝트의 기존 작업 규칙을 따른다.

별도 작업 브랜치 또는 worktree에서 작업한다. 브랜치 이름 예시는 `ui/aifect-streaming-first`이며 실제 생성·사용 여부는 확인 후 보고한다. 이미 같은 이름이 있으면 덮어쓰지 않는다.

이 자료는 최신 요구사항 기준이다. 이전 시안만을 근거로 스트리밍 기능을 축소하거나 메시지를 하단에서 제거하지 않는다. 시안과 본문이 충돌하면 사용자가 명시한 동작·기능 요구를 우선한다.

## 3. 구현 범위와 단계

### 1차: 스트리밍 기반과 홈 · 부르기 · 마이

공통 하단 메뉴, 축소형 미니플레이어, 공통 목록·버튼·탭 스타일을 먼저 정리한다.
그다음 홈, 홈의 추천·차트·최신곡·발견, 홈에서 연결되는 내 음악/좋아요/플레이리스트/최근 감상, 부르기 첫 화면, 마이 첫 화면을 기존 데이터와 연결한다.

목록·보관함 등 연결 화면은 기존 기능을 살리고, 실제 동선이 완성되는 범위에서 함께 조정한다. 첫 화면만 꾸미고 탭·버튼을 빈 동작으로 남기지 않는다.

1차 구현 후 실제 실행 화면, 변경 요약, 테스트 결과를 사용자에게 보여준다. 이 검토 전에는 전체 앱을 일괄 재작성하거나 운영에 배포하지 않는다.

### 2차 이후: 동일한 규칙으로 확장

커뮤니티, 공개 프로필, 메시지, 음악 상세·전체 플레이어의 추가 시각 정리, 스튜디오, 선물·지갑·설정은 1차 검토 뒤 순차 확장한다. 1차에서도 이 화면들의 기존 진입과 기능은 유지해야 한다.

## 4. 공통 탐색 구조

하단 메뉴와 순서는 **홈 · 커뮤니티 · 부르기 · 메시지 · 마이**를 유지한다.
음악 검색은 주요 화면 상단에서 쉽게 접근하도록 한다. 부르기 안에서는 부를 곡 찾기를 우선한다.

같은 기능의 여러 바로가기는 허용한다. 다만 홈과 마이의 '좋아요한 노래'가 같은 목록·상태를 공유해야 한다. 이름만 비슷한 중복 보관함이나 별도 데이터 저장소를 만들지 않는다.

목록에서 뒤로 돌아오면 가능한 범위에서 스크롤 위치, 선택한 탭, 검색 조건을 보존한다. 시스템 뒤로가기와 화면 닫기를 구분하고 기존 딥링크를 깨뜨리지 않는다.

## 5. 홈과 스트리밍 요구사항

### 홈의 4개 탭

| 탭 | 역할 | 구현 요구 |
|---|---|---|
| 추천 | 바로 들을 곡과 최근 음악을 제시 | 기존 추천 데이터 사용. 과도한 배너보다 음악을 먼저 보이게 함. |
| 차트 | 인기 음악을 연속으로 탐색·재생 | 기존 순위·집계 기준 유지. 기존 기간·필터가 있으면 보존. |
| 최신곡 | 새로 공개된 음악 탐색 | 기존 공개일·정렬 의미를 보존. 표시 가능한 공개 음악만 사용. |
| 발견 | 취향·장르·아티스트 탐색 | 기존 장르·검색·발견 기능과 연결. 새 추천 엔진을 임의로 만들지 않음. |

4개 탭은 메뉴명만 남기지 말고 실제 콘텐츠와 연결한다. 탭 위치는 예측 가능하게 유지하고, 상단을 길게 스크롤해야 탭을 다시 찾는 배치를 피한다.

### 내 음악 접근

홈에서 내 보관함/내 음악 목록, 좋아요한 노래, 플레이리스트, 최근 감상에 명확한 바로가기를 둔다. 이름이 중복될 경우 보관함은 전체 저장 음악의 입구, 플레이리스트는 묶음 목록이라는 차이가 드러나게 한다. 최종 용어는 기존 데이터 구조를 확인해 통일한다.

마이에서도 같은 목록으로 쉽게 들어갈 수 있어야 한다. 프로필 관리나 지갑을 여러 단계 거쳐야 음악을 찾는 구조를 피한다.

### 실제 재생 동작

- 재생 버튼은 선택한 곡을 즉시 재생한다. 음악 정보와 아티스트 정보의 진입 동작도 일관되게 구분한다.
- 목록의 연속재생/전체재생, 셔플·반복·재생목록 등 기존 재생 기능은 축소하거나 삭제하지 않는다.
- 연속재생 버튼이 기존에 없는 경우 UI만 추가하지 말고 기존 재생 엔진의 지원 여부와 필요한 범위를 보고한다.
- 좋아요·담기 변경은 홈, 마이, 플레이어에서 동일하게 반영되어야 한다.
- 원곡·커버·듀엣 콘텐츠의 실제 분류와 재생·정산 관계는 기존 동작을 보존한다.

### 미니플레이어

기본 상태는 앨범 이미지, 곡명/아티스트, 재생/일시정지, 다음 곡 중심의 작은 바다. 셔플·반복·전체 재생목록 등 세부 기능은 확장 플레이어에서 접근한다.

화면 이동·플레이어 접기 때문에 음악이 끊기지 않도록 현재 재생 엔진과 상태를 재사용한다. 기존에 지원하는 백그라운드 재생과 외부 미디어 컨트롤도 회귀 확인한다.

미니플레이어와 하단 메뉴가 목록 마지막 항목을 가리지 않게 처리한다. 재생할 곡이 없으면 가짜 곡을 채우지 않는다.

## 6. 부르기 첫 화면

부를 곡 검색, 저장된 녹음 이어 하기, 솔로로 부를 곡, 참여 가능한 듀엣을 쉽게 찾는 구조로 바꾼다. 큰 홍보 배너와 설정 설명 때문에 실제 곡 목록이 화면 밖으로 밀리지 않게 한다.

듀엣에서 참여를 누르면 선택한 곡과 상대 파트 정보가 이어져야 한다. 곡·모드를 불필요하게 다시 선택하게 하지 않는다.

최근 합의한 가사 중심 녹음 화면, 파트 표시, 하단 설정 팝업 방향은 보존한다. 이번 1차는 부르기 진입 화면이 중심이며, 녹음 엔진·오디오 효과·부분 재녹음 로직을 무관하게 재작성하지 않는다. 실제 저장소의 최근 수정과 충돌하면 해당 부분을 분리해 보고한다.

녹음 화면 진입 시 스트리밍 오디오와 녹음 반주가 겹치지 않도록 기존 오디오 전환 동작을 보존한다. 녹음을 나갈 때 작업 유실을 막는 저장·확인 흐름을 회귀 확인한다.

## 7. 마이와 내 음악

마이에서는 내 음악과 내 활동·관리의 목적을 분리한다. 프로필/레벨 정보만으로 첫 화면을 채우지 않고 저장한 음악에 빠르게 접근할 수 있게 한다.

- 보관함: 좋아요한 노래, 플레이리스트, 최근 감상 등 다시 들을 음악.
- 공개 페이지: 다른 사람이 내 공개곡·커버를 듣고 팔로우·댓글·선물로 반응하는 공간.
- 내 작업/스튜디오: 녹음 초안, 업로드곡, 편집·공개 관리. 기존 역할에 맞춰 중복을 정리한다.
- 지갑·정산·계정 설정: 음악 감상 영역과 분리하되 기존 접근을 유지한다.

좋아요·플레이리스트 등의 수량, 프로필, 잔액은 실제 데이터만 표시한다. 없는 데이터는 0 또는 적절한 빈 상태를 표시한다.

## 8. 시안에서 그대로 구현하면 안 되는 것

시안에는 콘셉트 설명을 위해 생성된 예시가 포함되어 있다. 화면 승인은 아래 항목을 신규 기능이나 정책으로 승인한 것이 아니다.

| 시안 요소 | 적용 규칙 |
|---|---|
| 다운로드 / Offline | 현재 지원 여부를 확인한다. 미지원이면 이번 작업에서 숨기거나 제외하고 보고한다. 새 다운로드 기능을 임의로 개발하지 않는다. |
| 실시간 차트, 순위 변화 | 실제 갱신·집계 데이터에 맞는 명칭을 쓴다. 지원하지 않는 실시간·상승/하락 수치를 만들지 않는다. |
| AI 추천 문구 | 실제 추천 방식 이상의 개인화·AI 기능을 주장하지 않는다. |
| 크루 대화, 단체 대화, 공지 탭 | 실제 메시지 기능을 확인한다. 미지원 기능을 화면만 만들어 동작하는 것처럼 표현하지 않는다. |
| 예시 가수·곡·사진·숫자·날짜 | 실제 콘텐츠/기존 리소스로 바꾼다. 운영 화면에 하드코딩하지 않는다. |
| 재화·레벨·구독·정산 표시 | 현행 정책을 유지한다. 시안의 숫자·단위로 정책을 바꾸지 않는다. |
| 미세한 글자 오류, 잘못된 아이콘 | 올바른 한국어와 실제 기능에 맞는 아이콘으로 정정한다. |

현재 구현되어 있지만 이 시안에 보이지 않는 기능은 삭제 승인이 아니다. 기존 경로를 유지하거나 합리적으로 재배치하고 변경 목록에 기록한다.

## 9. 시각·사용성 기준

승인 시안의 다크 네이비 배경과 보라·핑크·민트 계열 강조를 참고하되 과도한 발광·그라데이션 때문에 작은 글자나 상태 구분이 약해지지 않게 한다. 기존 브랜드 로고와 리소스를 우선 재사용한다.

동일한 역할의 버튼, 제목, 곡 목록, 카드, 하단 메뉴는 공통 구성요소와 토큰으로 통일한다. 임의의 정확한 색상·크기 값을 '사용자가 확정한 값'으로 단정하지 않는다.

한 화면에 정보를 더 넣기 위해 글씨·터치 영역을 무작정 축소하지 않는다. 실제 안드로이드의 화면 크기, 시스템 글꼴 확대, 상태바·하단 안전영역, 키보드 표시를 확인한다. 긴 한국어 제목과 줄바꿈을 테스트한다.

빈 목록, 로딩, 네트워크 오류, 로그인 필요, 저장 실패도 화면 흐름의 일부로 처리한다. 색상만으로 상태를 알리지 않고 라벨·아이콘 등으로도 구분한다.

공유 UI 코드를 변경한다면 데스크톱 웹과 기존 다른 화면의 의도하지 않은 변경을 확인한다. 이번 작업을 웹 전체 리디자인으로 확대하지 않는다.

## 10. 검증 기준

아래는 목표 체크리스트이며 아직 실행·통과한 결과가 아니다.

- [ ] 추천·차트·최신곡·발견 각각에 진입해 실제 음악을 탐색·재생할 수 있다.
- [ ] 홈에서 좋아요한 노래와 내 플레이리스트를 쉽게 찾고 실제 목록을 열 수 있다.
- [ ] 마이에서 접근한 같은 목록이 홈과 동일한 데이터·상태를 표시한다.
- [ ] 목록의 곡 재생, 다음 곡, 기존 전체재생·셔플·반복·재생목록 기능이 유지된다.
- [ ] 곡을 들으며 하단 메뉴를 전환하고 플레이어를 접거나 펼쳐도 재생이 의도치 않게 끊기지 않는다.
- [ ] 좋아요 추가/취소와 플레이리스트 담기가 다른 화면에도 반영된다.
- [ ] 뒤로가기 후 탭·검색·목록 위치가 불필요하게 초기화되지 않는다.
- [ ] 부르기에서 곡 검색, 기존 녹음 이어 하기, 듀엣 참여 경로가 작동한다.
- [ ] 녹음 진입 시 오디오가 중복되지 않고 기존 녹음·저장 동작이 유지된다.
- [ ] 미니플레이어·하단 메뉴·키보드가 조작부나 목록 끝을 가리지 않는다.
- [ ] 작은 화면, 큰 글자, 긴 제목, 빈 상태, 오류 상태에서 잘림과 겹침이 없다.
- [ ] 기존 커뮤니티·메시지·공개 프로필·선물·지갑·설정의 진입 경로가 유지된다.
- [ ] 빌드/정적 검사/관련 테스트를 수행하고, 실행하지 못한 항목은 이유를 기록했다.

실제 기기/에뮬레이터 실행이 불가능하면 정적 점검과 런타임 테스트를 구분해 보고한다. 생성 이미지나 목업을 실제 실행 캡처로 제출하지 않는다.

## 11. Git 및 결과물

승인 시안과 이 지시서는 저장소의 적절한 문서 폴더에 보관하는 것을 제안한다. 예: `docs/ui/aifect-20261018/`. 기존 파일은 덮어쓰지 않는다. Git에 들어갈 문서는 공개 가능한 자료인지 확인한다.

변경은 기존 규칙에 맞춰 작업 브랜치에 작은 단위로 기록한다. 원격 push, PR 생성은 사용자가 지시한 범위를 확인하고, 운영 브랜치 병합·배포·스토어 배포는 별도 승인 전 진행하지 않는다. CI/CD의 자동 배포 조건도 확인한다.

1차 검토 결과물은 다음을 포함한다.

1. 실제 수정된 화면 캡처와 실행 확인 방법 또는 가능한 테스트 빌드.
2. 수정 파일, 기존 기능 보존 여부, 시안과 달라진 부분 및 이유.
3. 빌드/테스트 실행 결과와 미검증 항목.
4. 작업 브랜치와 실제 생성한 커밋 정보. push/PR/배포 여부는 각각 구분해 표시.
5. 2차로 남긴 화면과 작업 목록.

현재 확인하지 않은 저장소 정보, 원격 업로드 성공, 빌드 성공, 실행 성공을 추정해 보고하지 않는다.

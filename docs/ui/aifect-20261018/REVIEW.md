- 원격 push / PR / 운영 브랜치 병합 / 웹 배포 / 스토어 업로드: **모두 하지 않음**.

최근 10월 18일 커밋의 녹음·사회 기능 수정 중 일부는 웹에만 있었다. 이번 작업은 native의 `MainActivity`, `KaraokeActivity`, 녹음 엔진·오디오 효과·부분 재녹음·저장 로직을 수정하지 않았다. 웹 수정 사항을 전부 native에 이식했다고 주장하지 않는다.

좋아요와 플레이리스트는 별도 로컬 목록을 만들지 않고 기존 서버 상태를 다시 읽는다. 운영 화면에 시안의 곡명·인원·수치·날짜를 하드코딩하지 않았다. 미지원 다운로드·오프라인 기능은 추가하지 않았다.

시안은 색감과 정보 구조의 기준으로 사용했다. 기존 다크 네이비·라벤더·민트 토큰, 로고와 앨범 이미지를 재사용했다. 기존 한 줄 가사를 유지하면서 미니플레이어를 줄였으며, 좁은 화면/큰 글자에서는 바로가기를 2열로 배치한다. 긴 곡 제목은 최대 두 줄, 전체 제목은 곡 정보와 접근성 설명에서 확인한다.

## 실행 및 검증

검증 환경: Android 에뮬레이터, 390dp 폭(780×1688px, density 320), 기본 글자. 추가로 320dp 폭(640×1280px), 글자 130%를 검사한 후 원래 설정으로 복구했다.

실행 화면은 **기존 앱 코드를 에뮬레이터에서 실행한 캡처**다. 계정·음원·이미지·수량은 기존 instrumentation 테스트의 로컬 HTTP fixture이며 운영 데이터가 아니다. 오디오 fixture는 무음 WAV이므로 실제 소리·음질 검증과 구분한다. 실제 연결 휴대폰에 설치하거나 기존 앱 데이터를 바꾸지 않았다.

| 검사 | 결과 |
|---|---|
| Debug APK / instrumentation APK 빌드 | 성공 |
| JVM 단위 테스트 | 61개 통과, 실패/오류/건너뜀 0 |
| Android Lint | 오류 0, 경고 116. 모든 경고를 이번 작업에서 해결한 것은 아님. |
| 선택한 instrumentation 회귀 19개 | 18개 통과, 알림 목록 관련 1개 실패 — 아래 미해결 항목 참조. |
| 320dp / 글자 130% 테스트 | 1개 통과. 긴 제목·주요 조작부·마이 줄바꿈 캡처 확인. |
| 최종 듀엣 변경 후 관련 재검증 | 듀엣 진입 및 빈 상태/오류/로그아웃 테스트 2개 통과. |
| diff 공백 검사 | 통과 |

이번에 추가한 1차 동작 테스트 8개(일반 환경 7개, 작은 화면 1개)는 통과했다:

- 홈 4개 탭의 콘텐츠·재생, 차트 기간 요청, 발견 검색 조건 복원.
- 홈/마이의 같은 좋아요 목록, 플레이어의 좋아요 취소 후 목록 반영, 보관함 뒤로가기.
- 플레이리스트 담기 요청 후 홈/마이에서 동일 구성 확인.
- 미니플레이어 한 줄 가사, 하단 5개 메뉴 이동 중 동일 MediaController 유지, 확장/재생목록 닫기, 셔플·반복·다음 곡·명시적 재생 종료.
- 백그라운드로 이동해도 재생 상태 유지, 외부 MediaController pause를 화면에 반영.
- 부르기 검색/솔로/듀엣, 실제 KaraokeActivity로 원곡 ID·상대 녹음 ID·듀엣 모드 전달 및 스트리밍 정지.
- 저장된 PCM 초안을 기존 녹음 후작업 화면으로 다시 열고 파일 크기 보존 확인(마이크 권한 불필요).
- 빈 보관함, 로그인 필요, 듀엣 오류와 재시도 입구, 작은 화면·큰 글자에서 조작부 접근.

스튜디오 진입/수정, 기존 차트 기간, 전체 메뉴 진입, 공개 프로필·지갑·설정, 크루 관련 선택 회귀도 검사했다. 전체 저장소의 모든 instrumentation 테스트를 실행한 것은 아니다.

### 확인된 미해결 항목

`webParityGiftQuantityAndActivityHistory`는 실버 선물 5개 전송 요청과 수량/금액 검증까지 통과했지만, 바로 이어 연 알림 목록에 fixture 항목이 표시되지 않아 15초 대기 후 실패했다. 단독 재실행에서도 재현됐다. `/api/notifications?filter=all` 요청은 발생했고 알림 시트는 열렸으나 항목이 비어 보였다. **운영 데이터에서도 같은지, 시작 커밋부터 있었는지는 확인하지 못했다.** 알림 구현은 이번에 변경하지 않았지만 전체 회귀 통과로 처리하지 않았다. 검토 패키지에 실패 로그·캡처를 포함했다.

### 아직 검증하지 않은 항목

- 실물 휴대폰·안드로이드 태블릿의 실제 마이크 녹음, 모니터링, 키 조절, 음질·지연 및 Bluetooth/유선 헤드셋 전환.
- 실제 녹음 저장/게시와 중간 녹음의 작업 유실 방지 전체 흐름. 이번에는 기존 초안 복원과 파일 유지, 듀엣 진입/오디오 전환을 검사했다.
- 운영 로그인·실제 계정/결제·실제 음원의 서버 권한·저작권/정산 경로, 실물 기기의 잠금화면 미디어 컨트롤.
- 프로세스 강제 종료 후 상태 복구, TalkBack 전수 검사, 모든 기기/글자 크기/가로 화면.
- 최근 웹 전용 녹음 수정의 native 추가 이식. 이번 범위에서 녹음 화면을 덮어쓰지 않았다.

## 재현 방법

저장소의 `app/android`에서 JDK 17 이상(검증에는 Android Studio JBR)과 Android SDK를 설정한 뒤:

```powershell
./gradlew.bat -PaifectTest :app:assembleDebug :app:assembleDebugAndroidTest :app:testDebugUnitTest :app:lintDebug
adb -s <검증기기> install -r app/build/outputs/apk/debug/app-debug.apk
adb -s <검증기기> install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s <검증기기> shell am instrument -w -e class kr.co.aifect.app.DesignCaptureTest#streamingHomeTabsPlayAndRestoreDiscovery kr.co.aifect.app.test.test/androidx.test.runner.AndroidJUnitRunner
```

`-PaifectTest`는 저장소에 이미 있던 검증 옵션이다. **같은 native 앱 코드**를 `kr.co.aifect.app.test` / `AIFECT테스트`로 만들어 운영 앱과 나란히 설치한다. debug 서명이며 스토어 제출용 파일이 아니다. 테스트 실행 시에만 로컬 fixture 서버를 연결한다. APK를 일반 실행하면 기존 실제 서비스 연결 경로를 사용한다.

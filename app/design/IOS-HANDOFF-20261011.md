# 2026-10-11 최종 반영 기준 — Android 2.5.41 (54)

Mac에서 이 커밋을 pull한 뒤 iOS 네이티브 화면에 아래 변경을 적용한다. 이 문서는 실제 Android와 웹 구현을 기준으로 하며, 이번 Windows 작업에서 iOS 빌드·설치 검증은 하지 않았다. 기존 `screens/2.5.35` 캡처는 변경 전 화면이다.

## 서버 액자와 달성 보상 (최신)

- **이번 앱 업데이트 이후 새 액자는 서버 배포만으로 추가한다.** 프로필/음악/DM/크루 API의 `profile_frame`과 `profile_frame_artwork`를 사용한다. 알려진 아이템 이름만 허용하는 클라이언트 분기를 추가하지 않는다.
- Android는 Coil `AsyncImage`, iOS는 기존 `RemoteArtwork` 캐시를 사용한다. `/assets/`의 버전별 PNG/WebP 주소를 받으며 교체 시 새 파일명을 사용한다. 이미지와 새 지급 조건은 웹 서버의 `shared/player.js`에만 등록한다. 업로드 관리 화면은 이번 범위에 포함하지 않았다.
- 기본 CREW 로컬 리소스는 이전 서버 응답을 위한 호환용이다. 정상 응답에서는 원격 이미지를 우선한다. iOS도 코드 연결을 완료했지만 Windows에서 iOS 빌드·설치를 검증하지는 않았다.
- 유저 10레벨(4,500 XP): `player-level-10` 숲속 마법 화관. 크루와 무관한 영구 보상.
- 크루 3/4/5레벨(각 500/1,500/3,000 크루 XP): `crew-level-3/4/5`. 가입한 크루가 해당 레벨 이상이면 각 보상을 지급한다. 크루 탈퇴/레벨 미달 시 보관함에 유지하지만 사용은 제한한다.
- GET `/api/me/player`에서 서버 경험치로 미지급 보상을 자동 확인·지급한다. 이미 기준을 넘긴 유저도 다음 보관함/레벨 조회 때 받는다. 중복 지급과 자동 장착은 하지 않는다. 운영자 backfill도 기존 대상에게 지급할 수 있다.
- `inventory`는 보유 아이템, `rewards`는 미달성 미리보기다. 둘 다 `artwork`, `usage`, `reason`, `available`을 사용한다. 미달성 미리보기에는 장착 버튼을 만들지 않는다.
- 제공된 크루 LV.3/4/5 원본 이미지 안의 **CLAN** 글자는 원본 그대로다. 앱의 명칭은 크루로 통일한다.

## 프로필·액자·색상

- 사람 프로필 사진은 원형. AI 가수에는 플레이어 액자와 레벨을 붙이지 않는다.
- 아이템 보관함과 크루 기본 액자는 이전 커밋 `d5927d2`에 포함됐다. 기본 액자는 사용자 제공 **메탈릭 블루 미래형 CREW 엠블럼 프레임**으로 교체했다. 웹 `dist/assets/crew-basic-v2.png`, Android `player_frame_clan_aether.png`, iOS `ClanAetherFrame.imageset/clan-aether-v1.png`에 동일한 투명 PNG 원본을 넣었다. 네이티브 내부 리소스 이름은 호환을 위해 유지하며 이미지의 글자는 **CREW**다. `PlayerProgress.kt`의 리소스와 배치를 따른다. 이전 CLAN 캡처는 교체 전 디자인이다.
- **최종 결정: 작은 프사와 모든 채팅 프사에는 레벨을 표시하지 않는다. 채팅의 `LV.숫자` 텍스트도 제거한다.** 큰 프로필의 작은 레벨 배지만 유지한다. Android는 80dp 미만에서 배지를 숨긴다. 글꼴 크기에 따라 배지가 프사 절반을 가리지 않도록 높이·줄 높이를 제한한다.
- 홈 배너·새 음원·크루 진입·응원별 보상 배너는 `MusicSurfaces.kt`의 공통 배경을 사용한다. 네이비 `#27313B` → `#272735`(58%) → 플럼 `#35283B`에 왼쪽 위 민트 `#8EDDD2` 15% 방사형 빛을 겹친다. 일반 프로필 배경은 더 약한 5% 빛과 `#212733` → `#1A1E29` → `#251F2D`다. 웹 `design-surfaces.css`와 같은 기준이다.
- 파트너인 사람 프로필은 서버의 `partner_badge`를 이름 아래 작은 민트 인증 표시로 보여준다. null/빈 값은 표시하지 않는다.

## 채팅

- DM과 크루 채팅 모두 최신 대화를 아래에 둔다. 키보드·입력창 높이·첨부 이미지 크기 변경 시 하단 위치를 유지한다. 이전 대화를 직접 읽고 있을 때 새 메시지가 왔다는 이유만으로 강제 이동하지 않는다.
- 활성 대화에서는 미니 음악 플레이어를 숨긴다. **음악 재생 자체는 중지하지 않는다.** 대화를 닫으면 다시 표시한다.
- Android 참고: `SocialScreens.kt`의 `ChatHistory`, `MessageProfileAvatar`, `NativeScreens.kt`의 `visibleChatCount`.
- 크루 사진·가입 이후 대화만 읽기·계정별 로컬 캐시는 기존 구현을 유지한다.

## 정산 정책

- 세금·실제 결제 수수료 등을 제외한 정산 기준액으로 배분한다.
- 일반 창작자의 원곡/직접 개인 선물은 창작자 60%, AIFECT 40%.
- 파트너의 원곡/직접 개인 선물은 창작자 70%, AIFECT 30%.
- **커버곡 선물은 등급에 관계없이 가창자 70%, 플랫폼 30%, 원곡자 0%.** 커버 재생 실적은 원곡자 스트리밍 정산에 반영한다.
- 스트리밍은 모든 등급 50:50. 운영자가 월별 실제 결제·환불·수수료·세금 자료를 확인해 확정한다. 공급업체 매출 보고서를 자동 수집하는 기능은 아니다.
- 파트너는 확정된 누적 세전 스트리밍+선물 정산 100만원 이상 및 운영자 검증으로 승급한다. 환불·취소·자가 후원·부정 실적은 제외한다. 운영자 특별 선정도 가능하며 사유·감사 기록을 남긴다.
- 승급 이후 선물에만 새 비율 적용. 사용/출금으로 누적 승급 실적이 줄지 않는다. 환불/부정 실적 취소로 요건 미달이면 일반 등급으로 계산한다. 이미 기록한 선물의 배분율은 소급 수정하지 않는다.

## 다이아 지갑 API 및 iOS 구현

**구매/선물에 쓰는 골드와 정산받는 다이아를 별도 표시한다. 골드는 현금 정산 불가.**

- 1다이아 = 세전 100원 = 10골드. **500다이아 → 5,000골드**. 추가 10% 공제 없음.
- 월 마감으로 확정된 수익만 지갑에 적립한다. 소수 다이아도 보존한다.
- 다이아로 전환한 골드는 다른 사람에게 선물할 수 있다. 새로운 결제 수수료나 부가세를 재차 계산하지 않는다.
- 현금 정산은 최소 100다이아, 정산 계좌 등록 필요, 월 1회. 다음 달 25일 지급 예정이며 적용되는 원천징수는 별도 표시한다.

`GET /api/diamonds` (로그인 필수) 주요 응답:

```json
{
  "balance": 0, "balance_mw": 0, "available": 0, "cash_value_krw": 0,
  "diamond_krw": 100, "gold_per_diamond": 10, "min_payout_diamonds": 100,
  "partner": {"tier":"general", "badge":null, "qualified":false,
    "review_required":false, "eligible_krw":0, "threshold_krw":1000000},
  "history": []
}
```

`history`는 `id, kind, amount_mw, diamonds, gold, period, detail, created`다. `balance_mw/amount_mw`는 1/1000원 단위 정수이며 표시 금액은 서버의 다이아 값으로 사용한다. `partner`에는 승급 시 `basis`, `activated`도 있다.

`POST /api/diamonds/exchange`, `POST /api/diamonds/payout` 공통 요청:

```json
{"diamonds":500,"request_id":"client-generated-uuid"}
```

응답은 `ok,id,gold,wallet`. 요청마다 UUID를 만들고 **네트워크 실패 재시도에는 같은 UUID와 금액**을 보낸다. 금액 변경/새 작업에는 새 UUID. 서버가 원자적 잔액 차감과 중복 요청 방지를 수행한다. 요청 가능한 다이아는 양의 정수이며 소수 잔액은 남긴다. 성공 후 지갑과 골드를 함께 갱신한다. 409는 잔액/신청/환불 검토 상태가 바뀌었음을 표시하고 재조회한다. 잔액 로딩 오류를 0으로 보이지 않게 한다.

정산 계좌/명세 API는 기존 `/api/payouts/account`, `/api/payouts/me`를 유지한다. Android `DiamondScreen.kt`의 실제 필드와 동의 흐름을 따른다. 세금 식별정보를 로컬 파일·로그·Git에 저장하지 않는다.

마이/계정·선물함에서 **다이아 · 내 정산**으로 연결한다. Android는 별도 네이티브 시트를 사용한다. iOS도 이전 미구현 웹 경로에 연결하지 말고 같은 API로 네이티브 지갑을 구현한다.

## 운영자 기능

웹 `dist/diamonds.js`, 서버 `server/diamonds.js`에 운영자 파트너 검증/특별선정/취소, 월 스트리밍 수익 확정, 확정 수익 취소, 부정/환불 선물 제외가 있다. 완료된 달만 확정하며 증빙·사유·감사 기록을 남긴다. 관리자 권한 없이 호출할 수 없다. 기존 선물 월 마감은 다이아 적립으로 연결된다.

# iPhone 인수인계 · Android 2.5.130 (143)

2026년 11월 16일 KST 기준이다. Android에서 검증한 변경을 기존 SwiftUI 앱에 이어서 반영하기 위한 자료다. iOS 구현과 Xcode 검증은 후속 작업으로 남아 있다.

저장소는 `lsevenn77-dev/aimusic`이다. 이번 Android 변경과 기존 iOS 소스를 함께 담은 브랜치는 `feat/android-release-143-ios-handoff-20261116`이다. Mac의 미커밋 작업을 보존한 뒤 이 브랜치를 가져와 현재 iOS 작업 브랜치와 통합한다.

```sh
git fetch origin feat/android-release-143-ios-handoff-20261116
git log --oneline -5 origin/feat/android-release-143-ios-handoff-20261116
git diff --stat HEAD...origin/feat/android-release-143-ios-handoff-20261116 -- app/ios app/android
```

현재 iOS 프로젝트는 `app/ios/AIFECT.xcodeproj`, 생성 설정은 `app/ios/project.yml`이다. 화면과 녹음 흐름은 아래 최신 Android 소스와 이 문서를 기준으로 비교한다.

## 플레이·더빙·공통 화면

- 플레이의 노래 메뉴는 한 줄의 **추천 · 인기 · 듀엣 참여 · 내 초안**이다. 듀엣 참여와 내 초안이 이 행에 들어간다.
- 더빙 메뉴는 **추천 · 인기 · 장르 · 신규**다. 더빙 만들기는 **AIFECT 오리지널 바로 위**에 눈에 띄는 주 동작으로 둔다.
- 참여 가능·완성작 전환은 더빙 홈 상단에서 제거했다. 완성작은 둘러보기에서 열며, 기본 소개와 참여자 닉네임·공개 ID를 표시한다.
- 작품 소개와 배역 설명은 실제 텍스트가 잘릴 때 더보기를 표시하고, 펼친 상태에는 접기를 제공한다.
- 더빙 목록과 인기 목록은 목록 응답의 재생 시간을 사용해 `2인극 · 3:15`처럼 표시한다.
- 홈 인기 차트의 손가락 이동에 페이지 전환 애니메이션을 적용했다.
- 메시지는 상단에 **전체 · 공지 · 알림**, 같은 행 오른쪽에 새 대화 아이콘을 배치했다. 대화 행을 길게 누르면 해당 상대와의 기록 삭제 확인을 연다.
- 커뮤니티와 플레이의 오른쪽 상단 세 줄 메뉴를 제거했다. 마이의 설정 아이콘을 오른쪽 상단으로 옮겼다.
- 크루 게임의 테스트 중 문구를 제거했다.
- 내 커버·듀엣·더빙은 작품을 길게 누르면 해당 작품을 선택하며 다중 선택으로 진입한다. 선택 개수와 취소·삭제를 제공하고 삭제 전 개수를 확인한다. 일부 삭제가 실패하면 해당 작품의 선택을 유지한다.

주요 Android 화면은 `BrowseScreens.kt`, `CurrentExperience.kt`, `DubbingDiscovery.kt`, `MessageInbox.kt`, `ReferenceWorks.kt`, `NativeScreens.kt`, `ProfileScreens.kt`이다.

## 더빙 이어서 녹음

- 한 파트씩과 이어서 녹음을 선택한다. 이어서 녹음은 선택한 위치에서 한 번 눌러 시작하며 처음에만 3·2·1을 표시한다.
- 서버가 내려준 `cueStart`, `start`, `end`, `recordEnd` 타임라인으로 배경음과 효과음을 계속 재생한다. 상대 배역과 대사 사이에도 배경 재생 위치가 이어진다.
- 내 미녹음 대사 구간에만 마이크 입력을 파일로 저장한다. 이미 녹음한 대사와 상대 배역 구간은 건너뛴다.
- 완료한 대사는 개별 WAV와 대사별 기록으로 확정한다. 한 대사만 다시 녹음할 수 있고, 중단·백그라운드 전환·재진입 때 앞서 완료한 파일을 복원한다.
- 같은 화면에서 중단한 뒤 다시 시작하는 경우도 처리한다. 이전 오디오 작업의 정리가 끝난 뒤 새 작업을 시작하고, 새 카운트다운은 단조 증가 시계로 계산한다.
- 상대 배역과 저장된 대사를 듣는 동안에도 실제 배경 재생 위치로 진행 바와 시간을 갱신한다. 녹음 샘플이 들어오는 구간은 저장된 샘플 수로 녹음 시간을 표시한다.
- 배경 음향이나 마이크가 진행되지 않을 때는 제한 시간 후 오류와 재시작 안내를 제공한다. 녹음 입력은 취소를 막는 무기한 블로킹 읽기를 피한다.
- 전체 제출은 **내 배역의 모든 대사**를 녹음하면 활성화한다. 상대 배역의 녹음 완료와 독립적인 조건이다. 남은 내 대사 개수를 표시하고 제출 버튼은 하단에 접근 가능하게 둔다.

기준 소스는 `app/android/app/src/main/java/kr/co/aifect/app/NativeDubbingAudio.kt`와 `NativeDubbingScreen.kt`다. 순서·구간 처리는 `DubbingContinuousTest.kt`, 실제 WAV 저장과 재진입은 `NativePerformanceTest.kt`에서 검증한다.

## 마이크 입력과 듀엣 미리듣기

- 더빙의 한 파트씩·이어서 녹음 옆에는 작은 마이크 아이콘을 둔다. 누를 때 입력 음량을 조절하고, 조절 완료 후 닫는다.
- 입력 이득의 기본값은 100%이며 0~200% 범위를 사용한다. 샘플을 증폭할 때 허용 진폭으로 제한한다. 배경음이나 상대 음성의 재생 음량과 별도로 적용한다.
- 노래·듀엣 녹음 화면에도 입력 음량 조절을 제공한다. 파일에 저장하는 보컬과 직접 청음 경로에 일관되게 적용한다.
- 다른 사람의 반곡에 참여할 때 상대 파트 미리듣기를 제공한다. 실제 상대 목소리가 포함된 안내 음원을 선택한 가사 위치부터 듣고 멈출 수 있게 한다.
- 미리듣기는 마이크를 사용하지 않는다. 녹음 시작 때 미리듣기를 멈춰 오디오가 겹치지 않게 한다.

Android 기준은 `RecordingGain.java`, `karaoke/KaraokeActivity.java`, `karaoke/KaraokeEngine.java`, `karaoke/DirectMonitor.java`다. iOS에서는 `RecordingStudio.swift`, `AudioEditing.swift`, `VocalSettings.swift`의 기존 오디오 구조에 연결한다.

## 임시 저장과 업로드

- 녹음이 기기에 안전하게 확정된 뒤 **이 기기에 저장했어요**를 표시한다. 서버 저장은 `서버 저장 3/10`처럼 별도로 진행 상황을 표시한다.
- 대사마다 전체 저장 목록을 다시 쓰는 비용을 줄였다. 대사별 메타데이터를 원자적으로 확정하고 이전 저장 형식도 복원한다.
- 이미 업로드한 take ID를 재전송하지 않는다. 서버 응답이 유실되면 최신 녹음 상태의 take ID를 확인한 뒤 미완료 항목을 재시도한다.
- 서버 리비전을 사용해 대사를 순서대로 업로드한다. 실제 제출 때 서버가 완료 개수와 최신 리비전을 다시 검사한다.
- 사용자가 요청한 임시 저장 업로드는 녹음 화면을 닫은 뒤에도 이어간다. 같은 녹음에 재진입하면 진행 중인 저장 작업과 충돌하지 않게 동기화한다.
- 앱이 종료돼 업로드가 중단돼도 기기에 확정한 녹음은 남으며 다음 진입에서 이어 저장할 수 있어야 한다.
- 노래·듀엣 초안은 같은 메타데이터를 반복해서 디스크에 기록하지 않는다. 파일 쓰기와 오디오 종료를 UI 스레드에서 기다리지 않는다.

현재 서버 계약은 `/api/dubbing/projects/{project}/recording`, `/recording/{role}/start`, `/recording/{role}/lines/{line}?revision={revision}&take={takeId}`, `/recording/{role}/submit`이다. 대사 업로드는 48kHz 단일 채널 PCM16 WAV를 사용한다. 제출 시 명시적인 음성 공개 동의를 전송한다.

## 페이지 표시 속도

- 최근 목록을 계정·서버·요청 경로별 캐시에서 먼저 표시하고 새 응답으로 갱신한다. 다른 필터와 계정의 데이터를 섞지 않는다.
- 홈의 부가 미리 읽기는 최대 2개로 제한한다. 화면을 직접 열 때 요청이 부가 조회 뒤에서 막히는 병목을 제거했다.
- 곡 공유 링크는 홈의 부가 조회 완료를 기다리지 않는다. 이미 받은 곡 정보는 즉시 사용하고 같은 상세 정보를 연속해서 다시 요청하지 않는다.
- 마이의 갤러리와 상세 대시보드는 해당 화면 진입 시 조회한다. 보관함·최근 감상·내 프로필의 유효한 최근 응답을 재사용한다.
- 곡 상세와 플레이리스트를 닫으면 진행 중인 조회를 취소한다.
- 권한 확인·잔액·결제·음성 입장·녹음 업로드와 제출의 서버 검사는 매번 수행한다. 최근 공개 방 목록 캐시는 실제 입장 권한을 대신하지 않는다.
- 로그아웃·계정 전환·접근 거절은 해당 캐시와 화면 데이터를 정리한다.

Android 기준은 `NativeApi.kt`, `NativeReadCache.kt`, `MusicModel.kt`, `CurrentExperience.kt`, `DubbingDiscovery.kt`다. iOS의 `API.swift`, `AppModel.swift`, `SocialViews.swift`, `AIFECTApp.swift`와 대조한다.

## 인증과 서버 기준

- 운영 서버의 공개 주소는 `https://aifect.co.kr`이며 카페24 운영 구성을 사용한다.
- Android의 기본 Google 버튼은 Credential Manager를 호출한다. 브라우저 대체 인증은 별도 버튼이다. 카카오는 SDK를 사용하며 Android의 Apple 로그인은 브라우저 인증을 사용한다.
- 테스트 패키지는 `kr.co.aifect.app.test`, 출시 패키지는 `kr.co.aifect.app`이다. 패키지와 서명별 OAuth 등록을 각각 확인한다.
- 실제 Google 계정 인증 완료는 최근 작업에서 검증하지 못했다. Google Play 서비스의 네이티브 인증 화면 진입과 nonce 쿠키 처리를 확인했다.
- iOS 인증은 기존 Sign in with Apple과 iOS용 Google·Kakao 등록을 기준으로 플랫폼별로 검증한다.

## 확인한 결과와 남은 범위

- Android 단위 검사 120개와 속도·계정 분리·취소 관련 에뮬레이터 검사 9개가 통과했다.
- 별도 기능 검사에서 이어서 녹음 재시작, 기존 WAV 보존, 상대 구간 건너뛰기, 저장 응답 유실 후 재시도, 화면 종료 후 업로드, Google 네이티브 인증 경로를 검증했다.
- Samsung SM-F761N의 테스트 앱에서 운영 서버를 연결해 홈·노래·인기·듀엣·둘러보기·더빙·라이브·크루·랭킹·메시지·마이와 대표 상세를 읽기 전용으로 측정했다.
- 재진입 첫 내용은 노래 0.25초, 더빙 0.21초, 라이브 0.17초였다. 단일 Debug 측정이며 iOS의 예상 시간으로 사용하지 않는다.
- 홈 첫 내용 약 1.25초, 최신 홈 목록 갱신 약 3.14초, 첫 프로필 전체 조회 약 3.35초가 관찰됐다.
- iPhone에서는 Xcode 빌드·시뮬레이터·실기기 오디오·키보드·safe area·백그라운드 중단과 복원 검증이 남아 있다.
- 운영 계정의 작품 삭제, 실제 녹음 게시, 결제·선물 전송을 검사용으로 실행하지 않는다.

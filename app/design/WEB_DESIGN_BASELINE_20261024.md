# AIFECT 앱 전체 화면 설계 기준 — 현행 웹 대조본

기준: https://aifect.co.kr/ 모바일 화면과 Sites 216 소스, 2026-10-24 UTC 확인.
웹 커밋: `2d7605ec31495817fa17032d3948b35033e19e9c`.
이 문서는 앱 화면을 교체하기 위한 설계 기준이다. 앱 전체 구현·설치 완료 보고서가 아니다.

## 기준과 현재 작업 상태

사용자가 승인한 홈 시안의 정돈된 배치·원래 로고를 유지하면서, 메뉴·데이터·기능·진입 경로는 최신 웹에 맞춘다. 옛 네이티브 앱의 메뉴를 최신 기능의 근거로 사용하지 않는다.

- Android 실험 브랜치의 공통 스타일/홈 수정은 빌드와 단위 검사를 통과했지만 최신 웹과 기능 일치가 끝나지 않았다. 사용자 앱에 설치하지 않았다.
- iOS 전체 교체는 완료하지 않았다.
- 현행 웹은 읽기 전용으로 확인했다. 운영 사이트·DB·사용자 콘텐츠를 변경하지 않았다.
- 커뮤니티 `추천/팔로잉/크루`, 플레이 `솔로/듀엣` 중심, 마이 `내 음악/내 활동`으로 만든 앞선 시안은 최신 구조의 근거에서 제외한다.
- 실제 화면에서 확인한 내용과 소스에서 확인한 연결 화면을 아래에서 구분한다. 권한·빈 상태·공개 범위에 따라 보이지 않는 버튼을 모든 사용자에게 만들지 않는다.

## 1. 홈과 음악 탐색

현행 홈의 실제 섹션도 변경되어 있다. 옛 `Turn it up` 배너/3개 노래를 운영 데이터로 고정하지 않는다. 승인 시안은 모양의 참고이고 콘텐츠는 최신 응답을 따른다.

| 화면 | 웹 경로/근거 | 앱 설계 |
|---|---|---|
| 홈 | `#home`, 모바일 직접 확인 | 오늘의 음악 → 추천/차트/최신곡/발견 → 새롭게 도착한 음악 → 이번엔 내 목소리로 → 같은 노래, 다른 목소리 → 이번 주 자꾸 듣게 되는 음악 → 크루에서 나온 새 음악 → 취향을 나누는 플레이리스트 → 지금의 기분을 따라. 최신 섹션을 삭제하지 않고 세로로 연결 |
| 추천 진입 | 홈 추천 탭 | 승인 시안의 안정적인 여백·이미지·카테고리 버튼 계층 적용. 현재 추천 데이터 사용 |
| 인기 차트 | `#charts`, browse.js | 순위·작은 커버·제목·아티스트·재생, 기간 필터. 순위 외 장식 배지 최소화 |

| 발견 | `#discover`, explorer.js | 기분·장르 필터와 2열 음악 카드. 기존 필터 경로 보존 |

## 2. 커뮤니티 — 첫 화면은 토킹룸

**상위 탭: 토킹룸 / 크루 / 랭킹. 기본 토킹룸.** 공개 완료 작품의 팔로잉은 플레이 → 둘러보기에 있다.

| 화면 | 확인 수준 | 앱 설계/동작 |
|---|---|---|
| 토킹룸 목록 `#community` | 모바일 직접 확인 | 제목 → 상위 3탭 → 지금 열려 있는 토킹룸 → 방 제목/방장 검색 + 방 만들기 → 공개방 2열 카드 |
| 토킹룸 없음 | 모바일 직접 확인 | 현재 공개방 0개. `아직 열린 공개 토킹룸이 없어요.` 표시. 실제로 없는 방/참여 인원/추천방을 만들지 않음 |
| 방 만들기 | community-v3.js 폼 | 이름·공개 범위·정원·배경·공지. 크루 범위 선택 때만 해당 크루 입력. 만들기 전에는 서버 저장하지 않음 |
| 토킹룸 `#voice/:id` | voice-rooms.js / voice-room-template.js | 방 제목·공개 상태 → 최대 8개 음성 좌석 → 채팅 → 음악 미니플레이어 → 참여자/음향/홈/공유. 방장 승인 전 마이크 착석하지 않음 |
| 방 설정/음향 | 소스 확인 | 생성과 같은 필드. 입력·출력·모니터링·리버브 등 기존 제공 설정을 별도 시트로. WebRTC 엔진 변경 금지 |
| 크루 목록 `#community/crews` | 모바일 직접 확인 | 주목할 크루 → 검색 → 관심사·모집 상태·레벨·범위 필터 → 정렬/카드·목록 전환 → 실제 크루 목록. 좁은 화면 필터는 접어서 제공 |
| 크루 상세 `#crew/:id` | 공개 크루 직접 확인 | 대표사진 1개·이름·레벨/XP·인원·가입 상태 → 작품 / 멤버 / 공지 / 소개. 소속·권한이 있을 때만 채팅/관리 |
| 크루 작품 | 직접 확인 + community-v3.js | 현 멤버의 공개 완료 솔로·듀엣·더빙, 최신순. 제목 왼쪽 유형 표시. 대문 이미지 추가 금지 |
| 크루 멤버/공지/소개 | 연결 및 소스 확인 | 멤버는 역할과 프로필, 공지는 목록/상세, 소개는 실제 설명·규칙. 가입 신청을 자동 실행하지 않음 |
| 크루 관리 | community-v3.js / crew-integrated.js | 권한별 설정·가입 신청·역할·기록. 크루명 변경 30일 제한과 기존 서버 권한 유지 |
| 랭킹 `#community/rankings` | 메뉴 직접 확인 | 현재 운영 메뉴는 작품 랭킹 / AI 아티스트 / 관계 랭킹 / 크루 랭킹 / 더빙 랭킹, 5개. 좁은 폭 가로 탭 스크롤 |
| 랭킹 필터 | 직접 확인 + 소스 | 작품 솔로/듀엣/더빙, 주간 기본/월간. 준비 중·비공개 상태를 임의 데이터로 채우지 않음 |

방 내부 실시간 음성/착석은 실제 공개방이 없어서 이번에 실사용 검증하지 않았다. 운영 방을 생성해 검증하지 않았다.

## 4. 메시지와 알림

| 화면 | 근거 | 앱 설계 |

## 5. 마이 — 내 작품 / 내 활동

`#profile` 모바일 직접 확인. **프로필과 갤러리는 두 탭에서 공통 유지**한다. 실제 닉네임/사진/크루/통계를 하드코딩하지 않는다.

| 화면 | 앱 설계 |
|---|---|
| 상단 프로필 | 실제 사진·닉네임·설명·관계/크루·기존 프로필 수정. 사진에 보라색 P 배지, 닉네임 옆 편집 아이콘 재추가 금지 |
| 갤러리 | 현재 명칭 `갤러리`. 기존 사진만 표시, 삭제된 + 사진 올리기 타일 복구 금지 |
| 내 작품 기본 | 제작곡 → 커버 · 듀엣 · 더빙. 유형 필터 전체/커버/듀엣/더빙, 정렬·공개 범위는 현행 제공 범위 |
| 제작곡 전체 | `#producer-songs/:id`, 공개/본인 권한에 맞는 목록/관리 |
| 녹음/완료 작품 | 작품 상세와 관리 동작 구분. 커버를 원곡·제작곡에 섞지 않음 |
| 소속 아티스트 | 기존 실제 아티스트, 삭제된 새 아티스트 + 카드 복구 금지 |
| 스튜디오 | 기존 제작 관리 진입. 제목 앞 장식/버튼 앞 톱니바퀴 추가 금지 |
| 참여 기회 | 참여 가능한 듀엣 / 참여 가능한 더빙, 실제 열린 모집만 |
| 내 활동 | 보유 자산 → 내 레벨 → 보유 이용권 → 인벤토리/내 도구함 → 나의 관계/내 크루 → 받은 선물 → 최근 활동/알림 기록 → 계정 관리 |
| 프로필 편집 | `#profile/edit`, 실제 편집 필드·업로드/저장·실패 상태. 나가기 전 저장 안 된 편집 처리 |
| 관계 | `#relations`, 공개 동의·신청·수락 상태별. 타인에게 비공개 정보 노출 금지 |
| 갤러리/아티스트 전체 | `#profile-gallery/:id`, `#profile-artists/:id`, 소스 연결 유지 |

## 6. 선물·재화·이용권·도구함

보호 문서의 향후 설계와 현재 운영 화면을 구분한다. 현재 `#gifts`를 직접 열어 확인한 화면은 **실버 선물 / 골드 선물**, 골드 충전·결제, 보낸 선물 내역이다. `선물/테두리/테마/인벤토리` 네 탭을 현재 배포된 것으로 보고하지 않는다.

| 화면 | 앱 설계 |
|---|---|
| 선물함 `#gifts` | 실제 등록 이미지·가격·정렬 데이터. 실버/골드 등 실제 분류·구매 가능 여부 보존 |
| 선물하기 시트 | 수신자·실제 상품 → 수량 → 합계 → 명시적 선물하기. 선택만으로 발송/차감 금지. 기존 승인 모바일 5열·목록만 스크롤·잔액/충전/수량/전송 고정 제약 참고 |
| 골드 `#gold` | 실제 잔액·상품·가격·결제 상태. 결제 승인/실패/중복 처리 유지, 임의 가격 삽입 금지 |
| 선물 내역 `#gold/history` | 실제 발송 내역·수신자·수량·시간. 받은 선물과 구분 |
| 오늘의 실버 `#rewards` | 실제 미션·진행·수령 가능/완료. 가상 보상 수령 금지 |
| 받은 선물 `#gift-inventory` | 실제 인벤토리와 대상별 상태 |
| 내 도구함 `#inventory` | 실제 사용권/도구. 준비 중 상품을 활성 기능으로 만들지 않음 |
| 이용권 `#membership` | 실제 플랜·혜택·구매/해지 정책·보유 상태. 가격은 서버/현행 상품 기준 |
| 정산 `#payouts` | 실제 수익·조건·신청·처리 상태. 단순 디자인 교체로 금전 로직 변경 금지 |

## 7. 스튜디오와 계정

| 화면 | 앱 설계 |
|---|---|
| 스튜디오 `#studio` | 실제 업로드/제작곡/커버·관리 연결과 작업 상태. 감상·녹음·제작의 위치를 구분 |
| 업로드 `#upload` | 파일·크레딧·권리·분류·공개 등 기존 필드. 큰 단일 폼은 같은 순서의 섹션으로 묶고 오류를 해당 입력 아래 표시 |
| 작품 관리 `#manage/:id` | 실제 소유자 권한. 원곡·커버 편집 분기·정렬/가사/MR 처리 상태 유지 |
| 계정 `#account` | 계정·연결·환경설정·로그아웃·탈퇴 등 실제 제공 조작. 파괴 동작만 확인 |
| 로그인/동의 | 현재 인증·복귀 경로 유지. 로그인이 필요한 초안/내 작업/팔로잉은 빈 목록으로 위장하지 않음 |
| 정책/안내 | 기존 이용약관·개인정보·환불·가격·고객센터 링크. 앱 내 읽기 화면에서 원래 목적지 보존 |

## 공통 상태와 구현 검수

모든 목록에는 로딩, 실제 빈 상태, 검색 결과 없음, 오류/다시 시도, 추가 페이지, 권한/로그인 상태를 각각 설계한다. 서버 응답 전 0개/성공으로 단정하지 않는다. 뒤로가기·탭 이동 후 검색/정렬/스크롤을 적절히 복구한다.

검수 기준은 320/390/768 폭, 큰 글자, 긴 제목/닉네임, 키보드, 안전 영역, 미니플레이어 동시 표시다. 공개 음악·프로필·크루 등 콘텐츠의 원래 공개 범위를 따른다. 실제 마이크·블루투스·두 사용자 음성 참여·결제·발송은 디자인 확인과 별도의 기능 검증으로 기록한다.

## 네이티브 교체 전에 해결할 차이

| 영역 | 현재 확인된 차이 | 완료 판정 |
|---|---|---|
| 커뮤니티 | 네이티브는 옛 피드 중심. 최신 웹 토킹룸/음성 좌석과 동일 구조 아님 | 첫 진입 토킹룸, 공개 목록/검색/생성/권한/음성 수명주기 연결 후 |

| 마이 | 기존 네이티브 요약과 최신 작품/활동 대시보드 다름 | 프로필/갤러리 공통, 제작곡/완료 작품/활동 상태 연결 후 |
| 공통 스타일 | 실험 브랜치에서 임시 추정 표면색 사용 | 최신 웹 토큰과 승인 홈 스타일 비교 후 |

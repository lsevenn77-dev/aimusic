## 화면과 연결

- **듣기**: 추천·차트·최신곡. 실제 최신 앨범 한 곡을 먼저 보여주고 좋아요/최근 감상/플레이리스트 바로가기, MR이 준비된 곡 직접 부르기, 커버 피드, 공개 플레이리스트와 음악가로 이어진다. 한 곡뿐인 카탈로그를 최신곡/인기곡 섹션에 반복하지 않고, 빈 공개 플레이리스트와 개인화 섹션은 숨긴다.
- **검색**: 곡·사람·플레이리스트 통합 검색과 분류, 장르/분위기 탐색. 탐색 목록은 별도 시트로 열려 듣기 홈의 곡을 덮어쓰지 않는다.
- **부르기**: MR·가사 싱크가 준비된 곡, 네이티브 노래방, 에코·룸 리버브·룸 크기·목소리/반주 음량, 이어폰 실시간 청음, 녹음 재청음 및 커버곡 업로드.
- **커뮤니티**: 전체·커버곡·제작곡·팔로잉 피드, 실제 재생/좋아요/댓글 수, 좋아요·댓글·댓글 좋아요, 내 댓글 삭제, 프로필 팔로우. 사람의 프로필 안에서 제작곡과 커버곡을 나눠 보여준다. 원곡의 다른 커버 보기 → 커버의 원곡 듣기 → 준비된 원곡 직접 부르기를 연결한다. 피드 아래 음악가/공개 플레이리스트로 탐색을 이어간다.
- **보관함**: 좋아요, 내/저장한 플레이리스트, 최근 감상, 내 커버곡/제작곡 상태, 팔로잉. 목록 내 검색·제목/아티스트 정렬·전체 재생/셔플. 목록 만들기·이름/공개 여부 편집·곡 추가/삭제·순서 변경·목록 삭제. 기존 서버의 Free 2개 / Premium 10개 한도를 그대로 적용한다.

## 메뉴 설계 원칙

웹과 동일한 차콜 배경, 핑크–라벤더–아쿠아 로고, 작은 `AI와 음악의 만남` 태그라인을 사용한다. Manrope ExtraLight 글꼴은 APK에 포함해 오프라인에서도 표시하고, 라이선스도 `android/app/src/main/res/raw/manrope_ofl.txt`로 함께 포함한다. 주요 동작은 핑크, 부르기는 아쿠아로 구분한다. 앱 아이콘과 시작 화면도 웹의 얇은 A 심볼로 통일하며 과도한 움직임 없이 음악 이미지를 중심에 둔다.

음악 감상 → 다른 목소리 발견 → 직접 부르기 → 커뮤니티 감상의 흐름을 따른다. 하단은 듣기·검색·부르기·커뮤니티·보관함 순서다. 검색과 계정은 음악 감상을 방해하지 않으며, 화면 전체가 이미지 로딩을 기다리지 않는다. LazyColumn/LazyRow와 Coil로 화면에 필요한 이미지부터 로드한다. VIBE의 모듈식 목록을 참고하되 AIFECT 색상·곡·프로필만 사용한다. 파티방은 추후 기능으로 이번 버전에 넣지 않았다. 커버 인기 순위나 노래방 이용 횟수를 임의로 만들지 않으며 제작곡 차트와 부를 수 있는 곡 순위의 집계 기준을 화면에 표시한다.

## 로그인

이메일 로그인/가입은 네이티브 폼이다. Google은 Android Credential Manager 계정 선택, 카카오는 공식 SDK로 카카오톡 인증을 사용한다. 카카오톡 미설치 시에만 카카오 계정 인증 화면을 연다. Apple은 Android Custom Tab에서 제공자 인증 화면을 열고 앱으로 돌아온다. AIFECT 공통 웹 로그인 페이지를 먼저 열지 않는다.

Google 서버 클라이언트 ID는 `/api/me`에서 받고 `/api/auth/google/nonce`의 단회 nonce와 메모리 전용 쿠키를 ID 토큰 교환에 사용한다. 서버가 서명·발급자·audience·nonce를 검증한다. 카카오는 `/api/auth/kakao/token`에서 access_token_info의 `app_id`가 `KAKAO_APP_ID`와 일치하고 프로필 ID도 같은지 검증한다. 클라이언트가 전달한 사용자 ID/이메일로 로그인하지 않는다. 같은 provider/subject의 기존 웹 계정을 유지한다.

Apple 인증 시 앱이 랜덤 verifier를 생성하고 SHA-256 challenge만 서버에 보낸다. 인증 성공 후 2분짜리 단회 ticket을 verifier와 교환한다. ticket만 탈취해도 세션을 받을 수 없다. 인증 완료 링크에 세션/키를 넣지 않는다.

세션 쿠키와 진행 중인 verifier는 Android Keystore AES-GCM으로 암호화한다. API와 음원 HTTP 클라이언트는 AIFECT 원본에만 쿠키를 보내고 리다이렉트를 따라가지 않는다. 앱 로그아웃은 브라우저 세션에 영향을 주지 않는다. 이전 WebView 세션은 가져오지 않으므로 2.0 업데이트 후 한 번 다시 로그인한다.

백엔드의 `server/native-auth.js`, `server/mobile-auth.js` 및 `/api/community`와 함께 배포한다. 기존 `oauth_states`를 재사용하므로 새 DB 마이그레이션은 없다. Android 패키지/인증서 등록과 카카오 공개 네이티브 키 설정이 필요하다. 네이티브 키는 Gradle `aifectKakaoKey`로 지정하며 REST 비밀키/어드민 키는 APK에 넣지 않는다. 릴리스 및 Play 서명은 별도로 등록해야 한다.

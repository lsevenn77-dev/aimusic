# AIFECT 네이티브 Android 앱

버전 **2.1.3 (7)** · 패키지 `kr.co.aifect.app` · Android 8.0 이상 · targetSdk 36.

Kotlin / Jetpack Compose 화면과 Media3 플레이어를 사용한다. WebView, Capacitor, 웹 JavaScript 화면은 APK에 포함하지 않는다. 기존 Java 노래방 화면과 오디오 엔진을 직접 실행한다.

## 화면과 연결

- **듣기**: 추천·차트·최신곡. 오늘의 발견, 분위기별 믹스, 최근 감상/좋아요, 인기곡 요약, 새 음악, 공개 플레이리스트, 음악가를 가로 목록으로 보여준다. 데이터가 없는 개인화 섹션은 숨기며 순위·곡을 만들어 채우지 않는다.
- **검색**: 곡·사람·플레이리스트 통합 검색과 분류, 장르/분위기 탐색. 탐색 목록은 별도 시트로 열려 듣기 홈의 곡을 덮어쓰지 않는다.
- **부르기**: MR·가사 싱크가 준비된 곡, 네이티브 노래방, 에코·룸 리버브·룸 크기·목소리/반주 음량, 이어폰 실시간 청음, 녹음 재청음 및 커버곡 업로드.
- **커뮤니티**: 전체·커버곡·제작곡·팔로잉 피드, 실제 재생/좋아요/댓글 수, 좋아요·댓글·댓글 좋아요, 내 댓글 삭제, 프로필 팔로우. 사람의 프로필 안에서 제작곡과 커버곡을 나눠 보여준다. 원곡의 다른 커버 보기 → 커버의 원곡 듣기 → 준비된 원곡 직접 부르기를 연결한다. 피드 아래 음악가/공개 플레이리스트로 탐색을 이어간다.
- **보관함**: 좋아요, 내/저장한 플레이리스트, 최근 감상, 내 커버곡/제작곡 상태, 팔로잉. 목록 내 검색·제목/아티스트 정렬·전체 재생/셔플. 목록 만들기·이름/공개 여부 편집·곡 추가/삭제·순서 변경·목록 삭제. 기존 서버의 Free 2개 / Premium 10개 한도를 그대로 적용한다.
- **플레이어**: 네이티브 MediaSessionService, 백그라운드·잠금화면 제어, 이전/다음·탐색·셔플·반복, 다음 곡과 닫기 버튼이 있는 미니 플레이어. 로그아웃 상태에서는 서버의 60초 미리듣기 제한을 따른다. 무료는 현재 가사 한 줄, Premium은 현재 줄과 주변 가사를 표시한다. Premium 만료 시 전체 가사 캐시를 지운다.
- 음원 제작·업로드 및 정산용 웹 스튜디오, 약관·고객센터는 명시적으로 외부 브라우저를 연다. Android 골드 결제와 Play Store 출시는 이 버전에 포함하지 않는다.

## 메뉴 설계 원칙

음악 감상 → 다른 목소리 발견 → 직접 부르기 → 커뮤니티 감상의 흐름을 따른다. 하단은 듣기·검색·부르기·커뮤니티·보관함 순서다. 검색과 계정은 음악 감상을 방해하지 않으며, 화면 전체가 이미지 로딩을 기다리지 않는다. LazyColumn/LazyRow와 Coil로 화면에 필요한 이미지부터 로드한다. VIBE의 모듈식 목록을 참고하되 AIFECT 색상·곡·프로필만 사용한다. 파티방은 추후 기능으로 이번 버전에 넣지 않았다. 커버 인기 순위나 노래방 이용 횟수를 임의로 만들지 않으며 제작곡 차트와 부를 수 있는 곡 순위의 집계 기준을 화면에 표시한다.

## 로그인

이메일 로그인/가입은 네이티브 폼이다. Google은 Android Credential Manager 계정 선택, 카카오는 공식 SDK로 카카오톡 인증을 사용한다. 카카오톡 미설치 시에만 카카오 계정 인증 화면을 연다. Apple은 Android Custom Tab에서 제공자 인증 화면을 열고 앱으로 돌아온다. AIFECT 공통 웹 로그인 페이지를 먼저 열지 않는다.

Google 서버 클라이언트 ID는 `/api/me`에서 받고 `/api/auth/google/nonce`의 단회 nonce와 메모리 전용 쿠키를 ID 토큰 교환에 사용한다. 서버가 서명·발급자·audience·nonce를 검증한다. 카카오는 `/api/auth/kakao/token`에서 access_token_info의 `app_id`가 `KAKAO_APP_ID`와 일치하고 프로필 ID도 같은지 검증한다. 클라이언트가 전달한 사용자 ID/이메일로 로그인하지 않는다. 같은 provider/subject의 기존 웹 계정을 유지한다.

Apple 인증 시 앱이 랜덤 verifier를 생성하고 SHA-256 challenge만 서버에 보낸다. 인증 성공 후 2분짜리 단회 ticket을 verifier와 교환한다. ticket만 탈취해도 세션을 받을 수 없다. 인증 완료 링크에 세션/키를 넣지 않는다.

세션 쿠키와 진행 중인 verifier는 Android Keystore AES-GCM으로 암호화한다. API와 음원 HTTP 클라이언트는 AIFECT 원본에만 쿠키를 보내고 리다이렉트를 따라가지 않는다. 앱 로그아웃은 브라우저 세션에 영향을 주지 않는다. 이전 WebView 세션은 가져오지 않으므로 2.0 업데이트 후 한 번 다시 로그인한다.

백엔드의 `server/native-auth.js`, `server/mobile-auth.js` 및 `/api/community`와 함께 배포한다. 기존 `oauth_states`를 재사용하므로 새 DB 마이그레이션은 없다. Android 패키지/인증서 등록과 카카오 공개 네이티브 키 설정이 필요하다. 네이티브 키는 Gradle `aifectKakaoKey`로 지정하며 REST 비밀키/어드민 키는 APK에 넣지 않는다. 릴리스 및 Play 서명은 별도로 등록해야 한다.

## 무료 감상 광고

기존 `lsevenn88@gmail.com` AdMob 계정의 AIFECT 전면 광고를 사용한다. 무료 로그인 이용자가 곡을 자연스럽게 끝까지 재생하고 실제 감상 시간이 곡 길이의 90% 이상이면 1곡으로 집계한다. 5곡 뒤 다음 곡 경계에서 한 번 표시하고, 닫거나 표시 실패 시 재생을 이어간다. 미리듣기·건너뛰기·끝으로 탐색은 집계하지 않는다. 계정별 집계는 기기에 보관하며 광고 재고가 없어도 여러 광고를 연속으로 쌓지 않는다.

Premium은 집계·광고 요청·표시에서 제외한다. MainActivity가 화면에 있을 때만 표시하므로 앱 열기·백그라운드·잠금화면·노래방 녹음 중에는 전면 광고를 띄우지 않는다. 광고가 아직 준비되지 않으면 음악을 계속 재생한다. UMP 동의 상태가 광고 요청을 허용할 때만 SDK를 초기화/요청하며 계정 메뉴에 광고 개인정보 설정을 제공한다.

- 릴리스 앱 ID: `ca-app-pub-5910265378731607~4925860289`
- 릴리스 전면 광고 단위: `ca-app-pub-5910265378731607/4219283278` (`AIFECT_Android_5songs_Interstitial`)
- debug APK는 Google 공식 테스트 앱/광고 ID를 사용한다. `-PaifectTest` 자동 검증에서는 광고 네트워크를 끄고 표시 수명주기만 검증한다.
- `https://aifect.co.kr/app-ads.txt`에 해당 게시자 인증 문구를 게시한다. 출시 시 Play 개발자 웹사이트도 같은 도메인을 사용하고 AdMob에 스토어를 연결해야 한다. 현재 AdMob 앱은 스토어 미연결로 검토 필요/광고 게재 제한 상태다.
- 출시 전 UMP 지역별 메시지 설정과 실제 기기의 테스트 광고 표시/닫기를 검증한다. 배포 APK에서 테스트 광고를 실제 광고로 착각하거나 실제 광고를 개발 테스트용으로 클릭하지 않는다.

## 빌드

Java 21, Android SDK 36을 설치한 뒤:

```powershell
$env:JAVA_HOME='C:/Program Files/Eclipse Adoptium/jdk-21.0.11.10-hotspot'
$env:ANDROID_HOME='C:/Users/lseve/AppData/Local/Android/Sdk'
cd app/android
./gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

`local.properties`에 실제 SDK 경로를 기록한다. 예: `sdk.dir=C\\:/Users/lseve/AppData/Local/Android/Sdk`.
APK는 `app/android/app/build/outputs/apk/debug/app-debug.apk`.
Node 설치나 `cap sync`는 필요하지 않으며 사용하지 않는다.

`-PaifectTest`는 별도 패키지 `kr.co.aifect.app.test`로 빌드한다. 이 패키지의 디버그 빌드만 MainActivity의 `testOrigin` extra로 HTTP localhost 테스트 서버를 지정할 수 있다. 일반 앱과 release에서는 이 옵션을 무시한다.

## 오디오 엔진

- 48kHz AudioRecord/AudioTrack. 마이크는 녹음 버튼을 눌렀을 때만 권한을 요청한다.
- 에코 235ms, 감쇠 반복; 룸은 4 comb + 2 all-pass. 파라미터 램프와 피크 제한, 기기 내 dry PCM 보관.
- 이어폰 청음 기본 OFF. 유선/USB 권장. 블루투스는 지연 안내 후 선택하며 실제 지연은 기기에 따라 다르다.
- 스피커로 마이크를 출력하지 않는다. 이어폰 분리·통화/오디오 포커스 상실·앱 백그라운드에서 녹음/청음을 중단한다.
- 내 목소리 듣기와 청음 음량은 노래방 화면 상단에 표시한다. 재청음에서 효과/목소리/반주 음량과 -300~800ms 싱크를 재생 중 조절할 수 있다. 느리게/빠르게 버튼은 5ms 단위이며 기본값은 80ms다. 타이밍 변경은 20ms 크로스페이드로 반영하며 반주를 멈추거나 처음으로 되돌리지 않는다. 원본 녹음을 보존하고 마지막 설정으로 내보낸다. 최대 10분, 32kHz PCM16 stereo WAV로 업로드.
- 사용자 직접 녹음/공개 권리 확인 후 업로드한다. 서버가 변환·공개한 뒤 커뮤니티의 커버곡으로 나온다. 녹음은 화면을 닫으면 기기에서 삭제한다.

## 검증과 출시 범위

```powershell
$env:ANDROID_SERIAL='emulator-5580'
./gradlew.bat :app:connectedDebugAndroidTest -PaifectTest
```

- JVM 12개: DSP, 피크 제한, 잔향, 원본 보존, 싱크 이동·재생 중 타이밍 전환, WAV/리샘플링, 서버 원본 제한, 5곡 광고 집계·미리듣기/건너뛰기 제외·광고 누적 방지.
- Android: 네이티브 화면에 WebView가 없는지 확인, 메뉴 이동, 백그라운드 재생/재생바 닫기, 이메일 로그인/플레이리스트 생성, 세션 암호화, 외부 원본/경로 차단 및 노래방 무음 fixture, 실제 Media3로 5곡 완료 후 광고 한 번/일시정지/닫은 뒤 재생/Premium 제외 테스트. 2.1.2에서는 노래방 4개 테스트로 상단 청음, 재생 중 싱크 변경과 연속 재생, 마이크 보호를 확인했다.
- 백엔드: 단회 인증·verifier 불일치·재사용 거부·브라우저 세션 분리·커뮤니티 접근 검증과 기존 회귀 테스트.
- Android 테스트는 로컬 합성 데이터와 무음 WAV만 사용한다. 실제 이용자 로그인, 실제 마이크 녹음, 글 게시, 결제는 하지 않는다.
- 별도 실기기 확인 필요: Google/카카오/Apple 각 계정 인증 완료, 이어폰별 실제 왕복 지연/음질, 전화 수신/장시간 녹음, 녹음 업로드 후 청음.
- 디버그 APK는 설치 확인용이다. 스토어 출시는 별도의 릴리스 서명·계정/콘텐츠 심사·결제 정책 작업이 필요하다.

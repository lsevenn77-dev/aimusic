# 알림 진입 시 전체 읽음 · 1.0.7(21)

- 홈 알림, 메시지의 알림 탭, 노래방 위 알림 시트가 사용하는 공용 `ActivityHistoryView`에서 화면 진입·새로고침 시 자동으로 읽음 처리한다. 개별 ‘읽음’ 버튼은 제거했다.
- 서버가 반환한 `read_through` 범위로 처리하므로 첫 페이지 밖의 알림과 다른 분류의 알림도 포함한다. 이후 도착한 알림은 이 범위에 포함되지 않는다.
- 읽음 응답의 실제 미확인 개수로 알림 배지를 즉시 갱신한다. 이미 진행 중이던 이전 요약 응답으로 배지가 되돌아가지 않게 했다. 다른 계정으로 전환했거나 취소된 요청은 적용하지 않는다. 개인·크루 메시지 읽음 상태는 변경하지 않는다.
- 서버 연결에 실패하면 읽음으로 표시하지 않고 다시 시도할 수 있게 한다. 목록 재진입과 이전 페이지 조회도 서버의 읽음 상태를 사용한다.
- 알림 읽음 처리가 음악 목록·보관함의 캐시와 진행 중인 목록 조회를 초기화하지 않도록 했다. 알림 목록·개수는 캐시하지 않고 계속 서버에서 조회한다.
- 웹에는 동일한 서버 범위 기반 자동 읽음이 이미 있어 웹 소스/서버 API 변경은 필요하지 않았다.

## 검증

- iPhone 12 / iOS 26.2 시뮬레이터, 실제 계정에 쓰지 않는 fixture로 UI 검사 5개 통과: `ios-build21-notifications-v2.xcresult`.
  - 화면 진입만으로 55개 전체 범위 읽음, 배지 0, 개별 ‘읽음’ 버튼 제거, 이전 페이지/재진입에서 읽음 상태 유지.
  - 503 응답 시 NEW/미확인 수 유지, 다시 시도 성공 후 해제.
  - 읽음 처리 도중 도착한 추가 1개는 미확인으로 유지, 재진입 시 처리.
  - 댓글 알림에서 원곡 상세로 이동, 알 수 없는 종류는 커버로 표시하지 않음.
  - 미니플레이어가 있는 상태에서 하단 탭 9회 직접 터치.
- 첫 UI 실행에서 기존 댓글 검사의 첫 탭 전환이 감지되지 않았다. 미니플레이어 준비를 기다리고 버튼 중앙을 직접 누른 뒤 화면 진입을 확인하도록 검사를 수정했다. 최종 실행은 5개 모두 통과했으며 실패 실행을 성공으로 계산하지 않았다.
- 캐시 관련 검사 2개 통과: `ios-build21-cache.xcresult`. 알림 읽음 후 음악 목록 재조회가 네트워크를 추가 호출하지 않으며, 음악 변경과 계정 변경은 기존대로 캐시를 비운다.
- [자동 읽음 후 화면](parity/build21-notifications-auto-read.png). 알림의 NEW/배지는 없어지고 하단 채팅 배지 3개는 유지된다.
- 실제 APNs 발송과 실계정 읽음 API에 대한 종단간 검사는 하지 않았다. 운영 서버의 `read_through`/`through` 계약과 기존 웹 동작을 확인했다.

## 연결 기기 반영

- `AIFECT-1.0.7-21.xcarchive` Release 빌드와 서명 검증 성공. 테스트 응답 코드가 Release 바이너리에 없음을 확인했다.
- 연결된 iPhone 12에 기존 데이터를 유지하여 설치했다. `devicectl device info apps`가 `kr.co.aifect.app`, 버전 1.0.7, 빌드 21을 반환했다.
- 설치 후 실행 요청은 기기의 `Locked` 오류로 거절됐다. 잠금 해제 후 실행 확인이 남아 있다.
- 이 변경으로 심사 대기 중인 빌드는 교체하지 않는다. Cloudflare 음성 서버 배포 완료 내역은 [빌드 20 기록](REPAIR-20261117-BUILD20.md)에 추가했다.

## 수정

- `WorkspaceBrowser`의 게임 화면에만 문서 완료 시 호환 스크립트를 설치한다.
- 웹이 이미 완료한 `ready(epoch)` 요청이 실제 URL target보다 먼저 도착하면 해당 target이 활성화된 후 같은 요청을 한 번 다시 전달한다. 대기 중 동일 URL 이동을 반복하지 않는다.
- 새 화면의 begin, 이전 화면의 콜백, 자산 오류, 원래 20초 제한, 문서 종료를 존중한다. 본문 CSS나 인증·접근 권한을 강제로 변경하지 않는다.
- 새로운 웹 게이트가 배포되어 즉시 준비되는 경우에는 별도 재시도 없이 원래 동작을 유지한다.
- 기존 웹 네비게이션 허용 범위와 쿠키 복사 방식은 유지했다.

## 검증

- 운영 HTML에서 추출한 실제 이전 렌더 게이트를 fixture로 보존했다. `node --test app/ios/scripts/game-render-compatibility.test.mjs`: 원래 실패 재현, 일반·탭 target의 지연 완료, 즉시 준비, 중복 설치, 경로 변경·오래된 완료·실패, 자산 실패, 시간 초과·종료 등 8개 통과.
- 전체 사이트 로컬 fixture는 실제 Worker와 빌드 client를 사용하되 운영 HTML의 이전 게이트를 주입한다. 계정·크루는 임시 SQLite이며 쓰기 요청은 차단한다.
- 1차 iPhone 12 시뮬레이터 UI 검사: 크루 배너 → 표시·터치 가능한 대기실 → 연습 → 결과 화면 통과(35.878초). 이전 epoch의 실패 처리 보강을 포함한 최종 검사도 통과(26.763초, `../work/ios-jump25-final.xcresult`). 실제 [대기실](parity/jump25/lobby.png)과 [연습 결과](parity/jump25/practice-result.png)를 확인했다.
- 실제 기기 검사는 `testDeviceJumpPracticeWithExistingAccount`로 별도 opt-in한다. 기존 로그인 상태를 사용하며 공식 도전·점수 전송 없이 연습만 실행한다. 일반 테스트에서는 skip한다.

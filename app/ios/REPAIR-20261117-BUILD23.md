# 크루 메뉴·둘러보기·대본 입력 개선 · 1.0.7(23)

## 변경

- 크루 공지와 크루 관리를 별도 페이지 대신 6개 메뉴 아래의 선택 영역에 표시한다. 선택한 메뉴의 색을 유지하고 작품·멤버·소개로 바로 전환할 수 있다. 공지 새로고침, 공지 편집 후 재조회, 탈퇴 후 크루 목록 갱신을 유지한다. 공지 편집기는 닫을 수 있는 시트로 표시한다.
- 둘러보기의 별도 Orbit 그림·세로 메뉴를 노래·더빙에서 쓰는 `StudioSectionTabs`로 통일한다. 팔로잉·인기·최신은 같은 크기의 선 아이콘과 같은 캡슐 선택 표시를 쓴다.
- 입력란 밖의 본문을 탭하면 텍스트 입력을 끝내되 화면 이동이나 데이터 삭제를 하지 않는다. 텍스트 선택과 버튼 터치를 가로채지 않으며, 내비게이션 바·키보드 도구 모음은 각자의 동작을 처리한다.
- 대본 편집 중 뒤로 버튼은 키보드가 열려 있으면 입력만 끝낸다. 키보드가 닫힌 상태에서 나가려 할 때 기존 저장 확인을 유지한다.
- 기존 대본 붙여넣기 시트에 취소 버튼을 추가한다. 작성 화면으로 돌아오고 원문을 보관하므로 다시 열어 이어 쓸 수 있다.

## 점프러쉬 조사 — 실기기 실패는 미해결

- 사용자가 게임 배너를 누른 직후 대기실 전에 실패한다고 확인했다.
- 운영 도메인의 공개 게임 모듈 6개가 HTTP 200임을 확인했다.
- 임시 XCTest에서 iPhone 12 / iOS 26.2의 WKWebView와 앱의 실제 navigation delegate로 운영 URL을 익명 조회했다. 약 5.9초에 대기실과 로그인 안내가 표시됐다. 인증된 실기기 도전 실행을 검증한 것은 아니다. 이 운영 네트워크 진단용 임시 테스트는 소스에서 제거했다. 결과: `../work/ios-build23-live-probe.xcresult`.
- 실제 게임 JavaScript를 제공하는 로컬 서버에서 앱 배너 → 대기실 → 연습 실행 → 일시정지를 UI 검사했다. 운영 계정·공식 도전 횟수·점수에는 쓰지 않았다.
- 별도 웹 체크아웃의 점프러쉬 진입·서버 로컬 fixture 검사 16개가 통과했다. 로그: `../work/ios-build23-game-server.log`.
- 현재 확보한 정보로 실기기 실패 원인을 확정하지 못했다. 사용자에게 오류 문구와 기기 잠금 해제를 요청했다. 게임 로딩을 수정 완료했다고 보고하지 않는다.

## UI 검증

iPhone 12 / iOS 26.2 시뮬레이터에서 아래 6개 시나리오의 최종 실행이 통과했다.

- 크루 6개 메뉴 배치, 공지·관리 인라인 전환, 아래쪽 탈퇴 버튼 접근, 크루 찾기 후 복귀: `ios-build23-ui-recheck.xcresult`.
- 노래·둘러보기 메뉴, 메시지·마이 이동: `ios-build23-ui.xcresult`.
- 대본 직접 작성, 입력란 바깥 탭, 입력 중 뒤로 버튼, 내용 보존, 대사 작성·저장: `ios-build23-input-final.xcresult`.
- 대본 붙여넣기 취소·재열기, 원문 보존, 편집·복원: `ios-build23-ui.xcresult`.
- 실제 점프러쉬 클라이언트의 로컬 연습·일시정지: `ios-build23-ui.xcresult`.
- 웹 작업 화면에서 입력란을 눌러 키보드를 열고 문장을 입력한 뒤 내용·포커스를 유지: `ios-build23-web-input-final.xcresult`. WebKit의 비동기 입력 반영은 조건을 기다려 확인한다. 네이티브 바깥 탭 처리는 웹뷰에 개입하지 않는다.

초기 검사 실패는 최종 통과에 포함하지 않았다. 크루 관리의 화면 아래 항목은 스크롤 검증과 접근성 그룹을 보완했다. 입력 중 뒤로 버튼에 바깥 탭 제스처가 먼저 반응하던 문제는 내비게이션 바를 해당 제스처에서 제외하여 수정하고 재검증했다.

# Chat delivery without a new provider

Crew rooms, DM conversations and the DM inbox now subscribe to `/api/chat/events` while visible. The existing authenticated POST endpoints still persist messages in D1. SSE carries change notifications only; clients fetch new history using their last **history-read** cursor. A later POST response never advances that cursor or hides intervening messages from another sender.

This is an interim database-backed stream, not a distributed pub/sub broker. Each active connection checks indexed room/DM state and session/membership access once per second. Connections rotate after 20 seconds to bound database calls per invocation. No in-memory room registry is used, so separate Worker instances observe the same stored messages. There are no Ably credentials, new subscriptions or external chat accounts.

Clients display outgoing messages immediately with a sending state. Confirmed messages reconcile by sender and request ID. Failed requests expose manual retry with the same ID; server idempotency prevents duplicates after a lost response. Pending UI is memory-only and is not an offline outbox. Existing history remains in D1.

Hidden/background clients close their connection and catch up on resume. Network failures reconnect with backoff and fall back to history requests. Logout/session expiration and crew removal terminate the stream. History and write endpoints independently authorize every request. Role changes are reflected in chat names. Migration 0020 adds five indexes only; it does not change message content or signing material.

Android 2.5.2 / versionCode 15 uses its existing authenticated OkHttp client and cancels streams with the foreground lifecycle. Previous Android releases can continue to use the unchanged history API until upgraded.

Validation: 172 server tests; real local Worker + two Chrome accounts covering SSE, immediate feedback, reconnect, lost POST response, retry IDs, kick, roles, DM inbox/replies, an out-of-order POST response, and 105 missed messages across pages. Android device checks cover SSE reconnect/cancellation, pending reconciliation and native crew/DM UI; JVM tests and APK/AAB builds also run. Local timings are observations, not a production latency or concurrency guarantee.

Before substantial concurrency growth, load-test active chat connections and D1 usage. One stream per active screen still creates database work proportional to active users. Ably or a separately deployed Durable Objects broker can replace the notification transport later while preserving storage, history, request IDs and permissions.

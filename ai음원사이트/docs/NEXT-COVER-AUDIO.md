# 커버 MP3 256kbps / 공식 AI 팔로우

사용자 확정: 256kbps. 새 커버뿐 아니라 기존 커버 원본도 변환하며, 검증된 MP3로 연결을 바꾼 뒤 이전 WAV/FLAC을 삭제한다. 기존 Sites 프로젝트·D1·R2를 유지한다.

## 구현

- 새 녹음은 PCM 임시 저장·듀엣 믹싱을 유지하고, 최종 저장/업로드 때만 별도 Worker에서 MP3 256kbps stereo/32kHz로 인코딩한다. 작은 청크로 전달하고 진행률을 표시한다. 실패 시 녹음을 유지한다. Info/LAME gapless 정보를 기록해 시작 지연·끝 패딩이 듀엣 타임라인을 바꾸지 않게 한다.
- 기존 커버는 운영자 전용 ‘커버 파일 압축’ 화면에서 선택한다. WAV/FLAC의 실제 `original_key`를 읽어 MP3 256kbps stereo/44.1kHz로 변환한다. 코덱·비트레이트·길이(원본과 2ms, DB와 50ms 이내)·파일 크기 감소·SHA256 업로드/재다운로드를 검증한다. 검증 후 DB 포인터를 원자적으로 바꾸고, 새 파일의 저장 상태를 다시 확인한 뒤 정확한 이전 원본 키만 삭제한다. 기존 스트리밍 AAC·Premium AAC·MR·가사·결제 기록은 유지한다. 본인 커버 다운로드는 MP3를 제공한다.
- 보관/고음질 처리기와 상호 배타적인 작업 획득 조건을 적용한다. 미완료 교체 작업은 재개하고 실패 변환은 최대 3회 시도한다. 더 작은 무손실 파일은 용량 증가를 피하기 위해 유지하고 기록한다. 이미 교체한 원본을 삭제한 후에는 무손실 원본으로 복원할 수 없다.
- 공식 봇이 응원 댓글/무료 선물을 성공시킨 창작자를 한 번 팔로우한다. `ai_support_follows`로 사람의 `follows`와 분리한다. 실패/스킵/중복 작업은 새 팔로우를 만들지 않는다. 기존 성공 응원 대상도 migration에서 연결한다. 모든 공식 팔로우는 감사 기록을 남긴다. 프로필 총 팔로워에는 ‘AI N 포함’을 표시하고 목록에 AI 배지를 표시한다. 실제 팬 수·랭킹·정산 쿼리는 기존 사람 팔로우 테이블을 사용한다.
- 곡 상세 커버 목록 기본값을 ‘전체’로 변경하고 ‘전체·솔로·듀엣·랭킹’에 서버의 실제 개수를 표시한다. 분류가 비어도 다른 분류에 곡이 있으면 전체 보기 링크를 제공한다. 보고된 ‘별일 아닌 것처럼’은 공개 API에서 솔로 0, 참여 대기 듀엣 1임을 확인했다. 분류 데이터를 임의 수정하지 않는다.

## DB 변경 — 아직 운영 미적용

1. `0072_medical_madame_masque.sql`: 기존 커버 변환 작업/lease/checksum/감사 대상 테이블과 큐 인덱스.
2. `0073_tan_karen_page.sql`: 공식 AI 팔로우 테이블·유형/성공 작업 검증·감사 트리거, 기존 성공 응원 대상 연결. 유료 원장 및 사람 팔로우 변경 없음.

## 확인한 결과

- 3분 합성 입력: WAV 23,040,044B → MP3 5,762,304B (약 75% 감소). FFmpeg 복호화 샘플 수 일치.
- Chrome 실제 페이지: 45초 듀엣 렌더/MP3/복호화 1.21초(모바일 폭 에뮬레이션 1.22초), 1,442,304B, 타임라인 차이 0ms. 녹음 PCM 유지.
- 실제 Python/FFmpeg HTTP 왕복: 기존 WAV 768,044B → MP3 193,976B, 저장 후 재다운로드/검증 → 포인터 교체 → 이전 원본 삭제 순서 확인.
- 권한·CSRF·lease 만료·잘못된 checksum·원본 상태 변경·다른 처리기·실패 재시도·삭제 멱등성·다운로드 소유권을 로컬 SQLite/R2 fixture로 검사한다.
- 정상 업로드 파이프라인도 새 MP3의 복호화 길이를 사용하여 공개된다.
- AI 팔로우 멱등성·실패 원자성·사람 지표 분리·차단·PC/모바일 표시를 확인한다.

## 배포 및 복구

운영 웹/DB를 먼저 반영하고 기존 `/root/aifect`의 `worker.py`, `cover_compression.py`, `Dockerfile`을 배포한다. 운영 `.env`를 읽거나 교체하지 않는다. `docker compose -p aifect -f compose.yml up -d --build --no-deps transcoder`만 사용하며 다른 서비스/컨테이너를 제거하지 않는다. 2026-10-24 읽기 확인한 운영 `worker.py` SHA256은 `45fd1d8324d3860f047a056383883f8b9c42fe6cb2e76819efd3d6976f7746cc`로 현재 브랜치 기반 코드와 일치했다.

실패 시 새 변환 예약을 중지하고 이전 변환기 이미지/코드를 복구한다. DB 포인터 교체 전 실패는 원본을 유지한다. 교체 후 청소 실패는 `committed` 작업으로 재개한다. 삭제가 끝난 파일의 무손실 복원은 불가능하므로, 이미 MP3로 교체된 트랙은 유지한 채 소프트웨어만 복구한다. additive DB migration은 되돌리지 않는다.

## 미검증

실제 Android/iOS 저사양 기기의 인코딩 속도·메모리·Safari gapless 재생, 실제 가창 음성의 청감 AB 비교는 미검증이다. 256kbps도 손실 압축이며 원음과 동일하다고 주장하지 않는다. 운영 기존 커버 변환 개수/절감량/삭제 여부는 운영 적용 후 기록해야 한다.

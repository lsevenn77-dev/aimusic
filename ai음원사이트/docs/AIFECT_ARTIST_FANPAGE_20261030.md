# 아티스트 팬페이지 개편 (배포 전 후보)

## 적용 범위

모든 #artist/:id 상세 페이지. 기존 공유 음악 리스트, 재생·좋아요·팔로우 API, 공통 셸, 하단 플레이바는 유지한다. 전용 artistMusicList를 재사용한다.

## 데이터와 권한

- artist_fan_settings: 배경 버전·형식, PC/모바일 초점, 상세 소개·콘셉트·세계관.
- artist_photo_layout: 기존 artist_photos의 순서와 캐러셀 선택만 저장한다. 이미지 객체는 중복 업로드하지 않는다.
- artist_fan_posts / artist_fan_likes / artist_fan_reports: 아티스트별 응원글·답글·공식 소식·좋아요·신고. 곡별 comments와 분리한다.
- artist_fan_operators: 제작자가 제작자 프로필 ID로 승인한 공식 운영자. 운영자에게 재위임 권한은 없다. 대표 프로필 사진 편집은 기존 제작자 권한을 유지한다.
- 신고는 별도 테이블에 접수한다. 기존 곡별 신고 구조를 변경하지 않는다.

0080_artist_fanpage.sql과 0081_artist_fan_operators.sql은 신규 테이블만 추가한다. 기존 기록을 수정·삭제하거나 운영 DB에 적용하지 않았다. 기존 20장 초과 갤러리도 보존하며 새 업로드만 20장으로 제한한다. 순서 미설정 사진은 기존 최신순, 캐러셀은 처음 10장이 기본이다. 이미지 저장 경로는 기존 images/artist/:id/ 아래를 재사용한다. 계정 삭제 시 새 텍스트·운영자 권한도 정리한다.

## UI

프로필 헤더 → 독립 3D 포토카드 캐러셀 → 홈/음악/갤러리/팬라운지/소식/프로필. 사진 0장은 캐러셀 숨김, 1장은 정적 표시, 최대 10장 노출. 5초 자동 넘김과 수동 이동·스와이프·키보드, 호버·포커스·터치·문서 숨김·확대 중 일시정지, reduced-motion을 지원한다. 라우트 정리 시 타이머와 이벤트를 해제한다.

헤더 업로드는 JPG/PNG/WebP·5MB·가로세로 320~8000px를 검사한다. 서버에서도 형식과 크기를 검증한다. 배경에만 네이비 오버레이·가장자리 블러와 페이드를 적용하며 로딩 실패 시 배경 레이어를 제거한다. 제작자는 미리보기와 PC/모바일 초점을 조정할 수 있다.

팬라운지는 20개 단위 피드·답글 더보기, 작성자 수정/삭제, 명시적 좋아요 PUT/DELETE, 신고, 제작자/공식 운영자 고정을 지원한다. 삭제 글은 답글 연결을 위해 본문을 지운 표식으로 유지한다. 모든 본문은 텍스트 이스케이프하며 서버 권한·요청 ID·빈도 제한·연속 중복 검사를 수행한다.

## 로컬 검증

`tests/preview-fanpage.mjs`는 메모리 SQLite/R2 모형과 저장소의 기존 샘플 이미지로만 실행한다. 이 fixture는 운영 데이터가 아니며 배포 화면에 가짜 데이터를 추가하지 않는다. `node tests/preview-fanpage.mjs` 후 http://127.0.0.1:4198/#artist/photos-10 에서 확인한다. photos-0/1/3/10/20 경로로 사진 수별 시나리오를 확인할 수 있다.

자동 테스트: tests/artist-fanpage.test.mjs, tests/artist-gallery.test.mjs. 전체 검증은 AGENTS.md의 release:prepare / release:check를 따른다. 운영 배포 및 운영 DB 적용은 각각 사용자 승인 대상이다.

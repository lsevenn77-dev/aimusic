# AIFECT 통합 버튼·아이콘 스타일 확정 지시서

## 최우선 기준

첨부한 **「AIFECT / 통합 버튼 디자인」 원본 이미지**를 최종 시각 기준(source of truth)으로 사용한다. 이번 작업의 목표는 아이콘 자체를 새롭게 디자인하는 것이 아니라 **참조 이미지의 각 아이콘 모양·선·비율·배열을 그대로 재현**하고, 해당 규칙을 사이트 전체의 같은 역할을 가진 UI에 일관되게 적용하는 것이다.

프로젝트 루트 및 대상 하위 경로의 `AGENTS.md`를 먼저 읽고 모든 공통 규칙을 준수한다. 기존 정상 기능·데이터·백엔드 집계·클릭 이벤트·정렬·라우팅·계정 권한을 보존하며 명시된 스타일과 반응형 배치만 수정한다. 이미 존재하는 디자인 토큰·아이콘 파일·컴포넌트가 시안과 정확히 일치하면 재사용한다.

## 1. 원본에서 절대 바꾸지 말아야 하는 아이콘

- **재생수:** 작은 `▷` 선형 삼각형 + 숫자. 원형 외곽선이나 배경 없음. 미니멀 카운터.
- **좋아요:** 사진 속의 속 빈 하트 경로 그대로 + 핑크 숫자. 기본 상태에서 채운 하트로 변경하지 않음. 기존 활성 상태에 별도 표현이 있다면 상태는 보존.
- **댓글:** 사진 속의 말풍선 외곽선과 꼬리 형태 그대로 + 숫자. 박스나 pill로 감싸지 않음.
- **빼기:** 가운데 수평 마이너스 한 줄, 원형 테두리만 민트→퍼플→핑크 계열 그라데이션.
- **재생:** 사진 속의 비어 있는 삼각형 `▷`이 원 안에 있는 형태 그대로. 버튼 내부를 그라데이션으로 채우거나 삼각형을 꽉 찬 `▶`로 변경하지 않음.
- **메뉴:** 사진 속의 동일한 길이의 가로선 세 줄. 점 세 개·세로점·다른 햄버거 경로로 바꾸지 않음.
- **추가:** 사진 속의 중앙 `+` 모양 그대로, 그라데이션 원형 테두리.
- **숫자 드롭다운:** 긴 알약형/타원형 그라데이션 외곽 테두리, 굵은 숫자, 그 오른쪽에 작은 아래쪽 V형 chevron. 버튼 내부는 다크 네이비. 숫자와 화살표를 세로로 쌓지 않음.

**금지:** 새로운 아이콘 라이브러리 경로로 임의 대체, 아이콘 두께/각도/비율 변경, 모든 버튼을 꽉 찬 원형 그라데이션으로 변경, 재생수·하트·댓글에 외곽 테두리 추가, 과도한 글로우·입체 그림자·카드형 버튼 생성.

## 2. 스타일 토큰과 공통 컴포넌트

- 바탕: 현재 AIFECT 다크 네이비 색상과 기존 공통 컴포넌트를 그대로 사용.
- 액션 테두리: 부드러운 민트 `#8EDDD2` → 라벤더/퍼플 `#A78BFA` → 연핑크 `#E9A1CE`, 약 1.5px. 글로우 최소화.
- 액션 버튼 내부: 기존 다크 네이비, 기본 상태 채우기 없음. 원형 테두리의 외곽 지름과 아이콘 크기는 같은 목록 안에서 통일.
- 카운트 아이콘: 외곽선·별도 배경 없음. 텍스트 및 아이콘 중심선을 수평으로 맞춤. 숫자 `tabular-nums` 사용.
- 드롭다운 숫자: `font-weight: 700~800`, V형 화살표는 시안대로 숫자 우측. 열리면 chevron 방향만 위로 변경.
- 목록의 액션은 한 가로선에 나란히 놓고, 아이콘끼리의 기준선·클릭 영역·간격을 맞춤. 원형 액션의 시각적 지름과 드롭다운 높이를 맞추고, 실제 모바일 터치 영역은 시각적 크기를 늘리지 않고 가능한 40~44px 이상 확보.
- 원본 이미지의 색상·선·형태·간격을 기준으로 하되 페이지별 반응형 스케일만 조정.

재사용 가능한 공통 컴포넌트/스타일 (기존 코드 구조에 맞는 이름 사용)을 마련한다:

- `MetricInline` — 재생수/좋아요/댓글 같은 테두리 없는 정보 카운터.
- `OutlineGradientAction` — 빼기/재생/메뉴/추가 같은 그라데이션 테두리 버튼. **슬롯 안의 원본 SVG 경로는 변경하지 않는다.**
- `CountDropdown` — 숫자+V형 chevron의 pill 버튼.
- `RankDelta` — 이전 순위 대비 상승/하락/변동 없음 표시.

새로운 UI 라이브러리 도입 없이 현재 기술 스택의 방식으로 구현하고, 반복 마크업을 공통 컴포넌트로 정리한다. 선형 그라데이션 테두리는 `border-box / padding-box` 이중 배경 등 실제 CSS 방식으로 구현할 수 있으나, 원형/알약형 실루엣과 사진 속 스트로크를 바꾸지 않는다.

## 3. 재생수·현재 순위·이전 순위 변동

- 차트 **재생수**: `▷ 36`, `▷ 8,921` 등 선형 삼각형과 숫자만. 박스·테두리 없음. 실제 집계값 사용.
- **현재 순위**: 별도 버튼처럼 보이지 않는 굵은 숫자(1, 2, 3...). 기존 정렬 로직과 데이터 유지.
- **이전 순위 대비 변동**: 상승 `↑ 1`은 민트, 하락 `↓ 1`은 핑크, 변동 없음은 가는 회색 `—`. 각 방향의 아이콘과 숫자 정렬 통일. 신규 진입 등 기존 별도 상태가 있으면 현행 의미를 유지한다.
- 상승/하락은 기존 데이터 기준으로만 계산하며 예시 숫자로 하드코딩하지 않는다.

## 4. 적용 범위

홈 음악 리스트, 인기 차트, 최신곡, 플레이(노래/더빙/둘러보기), 곡 상세 및 커버/듀엣/참여작 리스트, 마이페이지/보관함/플레이리스트 등 **같은 유형의 카운터와 액션 버튼**을 사용하는 모든 곳을 찾아 통일한다. 페이지마다 원래 없는 액션을 추가하지 않는다. 곡 상세의 발매일·장르·재생시간 같은 기존 상세 정보도 이 작업 때문에 삭제하지 않는다.

PC와 모바일 화면 너비에서, 텍스트가 길거나 두 자릿수 이상인 숫자가 표시되어도 버튼이 찌그러지지 않고 액션 순서가 유지되도록 한다. 모바일 키보드·팝업·스크롤 동작과 무관한 다른 레이아웃 변경은 하지 않는다.

## 5. 이후 다른 아이콘에 재사용할 범용 규칙

**새 대상:** `[대상 페이지/컴포넌트명]`의 `[아이콘명 또는 역할]`.

이 대상을 AIFECT 「통합 버튼 디자인」 시안의 스타일 규칙으로 변환하라. 먼저 대상 아이콘의 **기존 기능·SVG 경로·상징·선 두께·가로세로 비율·상태 표현**을 확인하고 그대로 보존한다. 정보성 숫자/카운터라면 테두리 없는 `MetricInline` 스타일, 누르는 액션이라면 동일한 얇은 민트→퍼플→핑크 그라데이션 외곽선과 다크 네이비 내부를 가진 `OutlineGradientAction` 스타일을 적용한다. 수량을 펼치는 기능이라면 숫자가 굵은 `CountDropdown`을 사용한다. 기존 아이콘 자체를 새로운 모양으로 다시 그리지 말고 래퍼·색상·크기·정렬·상태 스타일만 공통 체계에 맞춘다. 호버/누름/포커스/비활성 상태는 최소한으로, 키보드 접근성과 터치 영역은 유지한다. 수정 전후 PC·모바일 캡처를 비교하여 디자인 기준 이미지와 아이콘 형태가 일치하는지 검증하고 변경 파일과 결과를 보고하라.

## 6. 최종 검증 및 보고

1. 원본 사진과 비교하여 재생수/하트/댓글, 마이너스/플레이/메뉴/플러스, 숫자 드롭다운의 **형태가 동일**한가?
2. 카운터에 테두리가 없고 액션에만 얇은 그라데이션 테두리가 있는가?
3. 숫자·화살표·순위 변동 표시가 정확하며 실제 데이터와 연결되어 있는가?
4. 기존 클릭/드롭다운/재생/좋아요/댓글/추가/메뉴/정렬 기능이 유지되는가?
5. PC·모바일의 여러 리스트에서 크기·간격·정렬·키보드 포커스·터치 영역이 적절한가?
6. 사용하지 않은 라이브러리를 추가하거나 데이터를 초기화/이동하지 않았는가?

완료 시 변경 파일 목록, 재사용 컴포넌트 위치, 적용 페이지, 실제 검증 항목 및 남은 차이를 정리해 보고한다. **디자인 기준 이미지와 다르게 아이콘을 독자적으로 해석하지 않는다.**

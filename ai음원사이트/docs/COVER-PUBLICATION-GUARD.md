# 커버 공개 종류 확인

215번은 운영자가 확인한 기존 두 작품의 분류만 정정했다. 과거에 잘못된 듀엣 값이 전송된 구체적인 사용자 조작은 확인되지 않았으므로 원인을 단정하지 않는다.

후속 수정은 녹음 화면의 선택 모드와 실제 공개 의도를 분리한다.

- 웹 녹음 및 파일 업로드: 공개 종류를 직접 선택해야 한다. 솔로 커버는 완성 작품, 듀엣 참여 모집은 이어 부를 상대를 모집하는 작품이다. 듀엣 모집에는 별도 동의가 필요하다.
- Android: 저장 후 게시 시 같은 선택을 제공한다. 이미 다른 사람의 녹음에 참여했다면 완성 듀엣으로만 저장하여 파트너 연결을 보존한다.
- API: `publish_as`가 전달되면 `cover_mode` 및 `duet_parent_id`와 일치해야 한다. 불일치는 레코드를 만들기 전에 거절한다. 생성 응답에 저장 종류를 반환한다.
- 웹은 생성 응답을 확인한 뒤 음원을 올린다. Android는 저장된 작품 메타데이터를 조회하여 종류·파트너·원곡을 확인한 뒤 업로드하며, 재시도에도 선택한 공개 종류를 유지한다.
- 녹음 모드와 다른 종류로 공개할 때 출력 길이도 공개 종류 기준으로 결정한다. 솔로는 녹음 길이, 듀엣 모집은 반주 전체 길이를 사용한다.

구형 앱과 열려 있는 이전 웹 화면은 `publish_as` 없이도 기존 API를 사용할 수 있다. 모든 사용자가 새 확인 과정을 거치게 하려면 웹 배포 후 새로고침 및 앱 업데이트가 필요하다. 실제 음성에서 가수 수를 추측하거나 이미 공개된 작품 전체를 자동 변경하지 않는다.

운영 DB 구조·기존 작품·재생수·선물·정산 변경 없음. 로컬 SQLite에서 불일치 거절, 솔로/모집/완성 듀엣 저장 및 목록 분리를 검증한다. Android 로컬 서버 테스트는 듀엣 녹음에서 솔로 선택 시 전송값, 잘못된 저장 정보에 대한 음원 업로드 차단, 녹음 보존 및 재시도 종류 복구를 검증한다.

# AIFECT 전역 리스트형 UI·아이콘 정렬 통일 (2026-10-27)

## 목적
AIFECT 전역의 *목록형 행*에 쓰이는 아이콘 버튼의 시각적 크기, 테두리, 선 굵기, 간격, 오른쪽 정렬을 통일한다. 리스트별 기존 동작은 유지하고 필요한 버튼만 표시한다. PC·모바일·Android WebView에 반응형 적용한다.

## 우선 준수 사항
- 먼저 최신 작업 브랜치, AGENTS.md, AIFECT 디자인 토큰, 현재 실제 리스트 렌더러 및 CSS를 확인한다. 이 지시서가 위치한 로컬 복제본이 최신 운영 코드라고 가정하지 않는다.
- 전역 `button`, `svg`, `.icon-button` 전체를 일괄 덮어쓰지 않는다. *리스트 한정* 공통 클래스/컴포넌트(예: `aifect-list-row`, `aifect-list-actions`, `aifect-list-action`)를 생성하거나 기존 컴포넌트를 확장한다.
- 홈, 차트, 검색, 플레이(노래/더빙/둘러보기), 곡 이야기 커버 목록, 마이페이지(커버·듀엣·더빙/보관함), 플레이리스트·재생 대기열, 커뮤니티·랭킹 등 모든 리스트형 화면을 인벤토리하여 빠뜨리지 않는다. 목록이 아닌 큰 플레이어 조작부, 녹음기, 모달 주요 CTA, 카드 그리드, 하단 내비게이션은 동일 크기로 강제하지 않는다.

## 리스트 공통 시각 규칙
- 원형 라인형 버튼 외곽: PC 지름 28px, 모바일 24px. 내부 SVG는 각각 16~18px / 14~16px, stroke 약 1.8~2px, 중앙 정렬, 원형 테두리·명도 일관성 유지. 재생과 +의 외곽 크기를 반드시 동일하게.
- 메뉴(가로선 세 개, `menu`)는 *항상 리스트 행 최우측*; 재생(있다면)은 메뉴 바로 왼쪽; 녹음/참여는 재생 왼쪽. 하트·즐겨찾기·반복·셔플·다시듣기 등 기존 보조 행동은 목적에 맞는 그룹으로 정렬하며 가용 공간을 보면서 순서를 맞춘다.
- 목록 액션 클러스터는 flex, align-items:center, justify-content:flex-end, gap:PC 8px / 모바일 6px, flex-shrink:0, no-wrap 우선; 아이콘 크기/기준선/중앙점 통일. 곡명과 제작자 텍스트에는 flex:1; min-width:0 및 말줄임을 적용한다.
- 작은 아이콘에도 모바일 최소 44×44px (PC 40×40px) 실질 터치/포커스 영역을 제공하되 시각 영역은 24/28px만 차지하고, 인접 버튼과 터치 영역이 겹치지 않도록 한다. 320px 기기에서 공간 부족 시 별도 정렬된 2번째 행을 사용하고 버튼을 임의 제거하지 않는다.
- 작품형 리스트의 보조 텍스트에서 날짜·장르·재생시간 표시를 제거한다. API/DB 원본 데이터는 삭제하지 않는다. 영수증·알림·메시지·정산·관리 기록처럼 날짜가 본래 기능적으로 필수인 타임라인은 보존한다. 장르 선택 필터도 보존한다.
- `N⌄`는 숫자+아래화살표만 한 줄로 표시(앞의 + 없음), 눌러 참여작 펼침. 실제 0건의 처리 방식은 기존 의미를 유지하되 비활성 화살표가 헛동작하지 않도록 한다. `N⌄`와 참여용 원형 `+`는 디자인과 클릭 대상이 달라야 한다.

## 화면별 버튼 역할(기존 구현·정책 우선)
- 플레이 > 노래 추천/최신/MR 검색: 마이크(기존 커버 녹음 진입) + 필요한 메뉴. 녹음 전 반주 미리듣기 재생과 곡 이야기로의 자동 이동을 제거. 참여작 펼침이 남아 있다면 펼친 완성작에서만 감상 재생.
- 플레이 > 노래 듀엣: 참여 가능한 녹음 반곡만 표시; `+`는 기존 듀엣 참여 녹음, `▶`는 실제 녹음된 반곡이 있을 때에만 노출. 완성된 듀엣은 모집 목록에 섞지 않는다.
- 플레이 > 더빙 작품찾기: 작품(극본) 목록 행으로 작품 상세/대본 페이지로 이동. 새 더빙/기존 더빙 참여는 그 상세에서 결정; 리스트에 불필요한 녹음·재생 버튼 추가 금지.
- 플레이 > 더빙참여: 열린 세션별 빈 배역 수 표시; `+`로 배역 선택 → 녹음 흐름 연결. 재생 가능한 녹음 파일이 실제 있을 때만 ▶ 허용.
- 플레이 > 더빙 내 작업: 내 초안/제작 중/참여 중/완성 관리. 이어하기, 관리, 감상 동작 보존; 작품찾기에는 초안 중복 노출 금지.
- 플레이 > 둘러보기: 완성된 솔로커버·듀엣·더빙 감상 전용. 기본적으로 ▶(+기존 메뉴), 참여용 +나 MR 녹음 마이크 미표시.
- 곡 이야기 / 마이페이지 / 커버·듀엣·더빙: 원곡·반곡·완성작 상태를 기준으로 위 규칙을 재사용. 참여 가능한 작품에만 +를 띄우고, 완성작에 표시하지 않는다.
- 좋아요(하트), 다시듣기(replay), 반복(한 곡/전체), 셔플, 저장/추가, 재생목록 메뉴는 *이미 해당 목록이나 컨트롤 바에 있는 경우* 동일한 디자인 토큰과 기준선에 포함한다. 무조건 모든 행에 새로 추가하지 않는다. 셔플·반복은 재생 대기열/플레이리스트 제어부에 필요한 경우 기존 위치와 동작을 보존한다.

## 중요: 목록과 상세 페이지의 날짜·장르·재생시간 구분 (추가 확정)
- **삭제는 리스트형 목록의 간략 메타데이터에만 적용한다.** 작품 행/카드의 날짜, 장르, 재생시간을 제거해 목록을 간소화한다.
- **곡 이야기 페이지 상단의 원곡 상세정보, 개별 곡 상세, 커버곡·듀엣 작품 상세, 더빙 작품 상세, 음원/작품 정보 확인 화면에서는 날짜·발매일·제작일·장르·재생시간 등 기존 정보를 절대로 삭제하거나 숨기지 않는다.**
- 곡 이야기 페이지의 *하단 커버곡 리스트*에서는 해당 메타데이터를 제거하지만, 같은 페이지의 *상단 곡 상세정보*는 그대로 보존한다.
- 녹음기·재생기·정산·관리 화면처럼 시간 또는 날짜가 기능적으로 필요한 곳은 기존 표시를 보존한다.
- 리스트와 상세에서 공통 컴포넌트를 쓰는 경우 `variant` 등 명시적 화면 맥락으로 표시 규칙을 분리하고, CSS의 광역 선택자로 상세정보를 숨기지 않는다.
- 데이터베이스·API·상세 페이지의 날짜·장르·재생시간 데이터 및 표시를 삭제하지 않는다. PC·모바일 모두 회귀 테스트한다.

## 기능·안전
- 기존 onClick, data-* 핸들러, 오디오·녹음·더빙 창작기, 라우팅, 좋아요/반복/셔플 상태, 권한, API, 저장 흐름은 유지한다. 중복 버튼만 제거하고 기존 목적이 분명한 기능은 삭제하지 않는다.
- 모든 아이콘 버튼에 aria-label, title, 키보드 포커스, 눌림 상태, 비활성 상태 유지. 좋아요·셔플·반복의 활성 상태는 알아볼 수 있어야 한다.
- 공통 CSS 토큰을 정의하고 리스트 렌더링 코드에서 동일 클래스 사용. 기존 CSS에 흩어진 예외를 정리하되 다른 영역에 영향 주는 전역 셀렉터는 금지.

## 검증·산출물
- 주요 화면 목록을 실제 렌더링 상태로 검토하고 PC(1024/1440), 모바일(320/360/390/430), Android WebView까지 대응.
- 긴 제목·긴 닉네임·0명/여러 명 참여·버튼 1개/여러 개·비활성 버튼·좋아요 ON/OFF·셔플 ON/OFF·반복 모드·가로 오버플로·미세 클릭 영역 테스트.
- 특히 메뉴 오른쪽 고정, ▶와 + 같은 외곽 크기, N⌄ 줄바꿈 없음, 날짜/장르/재생시간 **목록에서만 제거**, 곡 이야기 등 **상세 페이지에서는 유지**, 녹음/배역 연결 및 재생 상태 유지 확인.
- 변경 파일 목록, 신규 공통 클래스/토큰, 조정한 화면 목록, PC·모바일 비교 스크린샷, 빌드/테스트 결과, 미수정 사항 보고. 사용자가 별도로 승인하기 전 운영 배포는 하지 않는다.


## 2026-10-28 사용자 추가 확인
목록은 간결하게, 상세 페이지는 정보가 충분하게 유지한다. 상세 정보와 DB/API 필드는 보존하고 운영 배포는 하지 않는다.

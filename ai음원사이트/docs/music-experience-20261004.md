# AIFECT: 스트리밍 + 참여형 음악 커뮤니티

## 제품 원칙
음악을 쉽게 재생하고 플레이리스트에 담는다. 마음에 든 음악에서 사람을 발견하고, 댓글·팔로우·메시지·선물·커버·듀엣·크루로 참여한다. 참여 결과물도 다시 스트리밍할 수 있는 음악이다. 녹음이나 업로드를 하지 않는 리스너도 동등한 기본 사용자다.

## 화면 구조
| 하단 메뉴 | 첫 화면의 역할 | 다음 행동 |
| --- | --- | --- |
| 홈 | 스트리밍, 최신 음악, 차트, 검색 | 재생, 내 플레이리스트, 좋아요, 최근 감상 |
| 커뮤니티 | 공개 음악 발견 | 제작곡·커버·듀엣·크루·팔로잉 |
| 부르기 | 기존 솔로·듀엣 녹음 진입 | 부를 곡, 녹음 초안, 참여할 듀엣 |
| 메시지 | 실제 대화 목록 | 대화 이어가기, 프로필에서 메시지 시작 |
| 마이 | 내 음악과 저장한 취향 | 내 플레이리스트, 공개 음악, 프로필 수정, 업로드 관리 |

커뮤니티의 '발견'은 최근 공개된 음악 피드이며 개인화 추천 알고리즘을 새로 구현한 것이 아니다. 크루는 상단 탭과 피드 첫 진입 카드로 제공한다. 실제 크루 검색·가입·기존 채팅 기능을 재사용한다. 실시간 접속, 노래 중, 파티방, 라이브, 존재하지 않는 미션/랭킹을 표시하지 않는다.

## 공통 음악 카드
1. 작성자 프로필과 공개 종류: 제작곡 / 커버 / 듀엣.
2. 앨범 이미지, 곡명, 설명, 원곡 연결 및 AI 아티스트 크레딧.
3. 우선 행동: 재생 + 플레이리스트 담기.
4. 보조 행동: 좋아요, 곡 댓글, 선물. 사람 관련 행동은 프로필의 팔로우·메시지로 연결.
5. 실제로 참여 가능한 듀엣에만 참여 버튼. 자신의 듀엣에는 참여 버튼을 표시하지 않음.

플레이리스트에 담을 때 선택한 녹음의 track ID를 유지한다. 커버나 듀엣을 원곡 ID로 치환하지 않는다. 원곡과 커버가 같은 플레이리스트에 함께 들어갈 수 있다. Android 새 플레이리스트 생성에서도 선택한 곡을 track_ids로 같이 전달한다.

## 프로필과 개인정보
방문자에게는 공개된 제작곡·커버·듀엣과 팔로워 수를 보여준다. 개인 플레이리스트·최근 감상·저장한 음악은 본인의 홈/마이/보관함에서만 접근한다. 타인의 팔로워 숫자를 누르면 내 팔로워 목록으로 잘못 이동하던 링크를 제거했다. 본인 프로필에는 자기 팔로우나 자기 선물 버튼을 표시하지 않는다. 공개 프로필이 없는 리스너는 프로필을 강제로 만들지 않고 보관함을 이용한다.

웹의 프로필 선물은 기존 profileGiftDialog를 사용한다. Android 프로필 선물은 응원할 공개 음악을 선택한 뒤 기존 선물 창을 연다. 금액·결제·정산·권한 로직을 변경하지 않는다.

## 코드 구성
### 웹
- dist/music-ui.js: 음악 종류, 참여 가능한 듀엣 판별, 프로필 목록 필터, 재생/저장 공통 카드, 보관함 진입.
- dist/music-experience.css: 네이비/플럼 토큰, 음악 카드, 프로필, 작은 화면/메시지 레이아웃.
- dist/home.js: 스트리밍 중심 홈과 명시적인 플레이리스트 저장.
- dist/community.js: 음악 피드 탭, 듀엣 감상/참여 구분, 랭킹 별도 화면.
- dist/browse.js: 공통 카드 사용과 메뉴 선택 상태.
- dist/improvements.js: 크루 전용 경로 community/crews, 마이/수정 분리.
- dist/views.js: 공개 프로필과 전체/제작곡/커버/듀엣 탭.
- dist/index.html, scripts/build.mjs: 공통 모듈 및 스타일 로딩.

### Android 네이티브
- MusicCommunityScreens.kt: SaveMusicButton, MusicCommunityScreen, MusicProfileHeader, MyMusicScreen.
- NativeScreens.kt: 실제 하단 5개 메뉴, 프로필, 공통 음악 목록/카드의 담기 진입.
- MusicModel.kt: 선택한 음악 저장 대상, 새 플레이리스트의 초기 곡 유지, 커뮤니티 로딩/오류/취소 상태.
- SocialScreens.kt: 기존 메시지 화면을 독립 탭/프로필 진입 시트 양쪽에서 재사용.
- BrowseScreens.kt: 홈 대표곡·선반에서 플레이리스트 담기.

## 검증 및 적용 범위
- 웹 로컬 테스트: 221개 통과. 별도 로컬 API 서버가 필요한 기존 api.test.mjs, mobile-auth.test.mjs는 이번 실행에서 제외.
- Android compileDebugKotlin, testDebugUnitTest 성공. 기존 단위 테스트 34개, 실패/오류/스킵 0.
- 실제 Chrome에서 빌드된 웹 파일을 실행: 320/390/430/1280px, 320px 큰 글씨 확인.
- 테스트 API 응답만 사용하는 브라우저 검증: 커버와 듀엣의 정확한 ID로 플레이리스트 저장, 저장 목록 재진입, 팔로우, 댓글, 크루 경로, JS 오류 없음.
- 캡처는 로컬 웹의 실제 렌더링이며 예시 데이터. Android 실기기 캡처가 아님.
- 실제 휴대폰의 터치/스크롤/오디오 지속 재생 회귀 검증은 배포 전 별도 수행 필요.
- 기존 녹음 수정본과 다른 미커밋 작업을 보존. 수정 전 파일 및 해시 기록을 별도 작업 폴더에 백업.
- 이번 작업은 로컬 소스 수정·빌드·테스트만. Git 커밋/푸시, 운영 배포, DB 변경, APK 설치, Play 제출 없음.

## 다음 배포 승인 전 확인
실제 Android 화면 크기와 큰 글씨에서 하단 메뉴·담기 창·프로필을 확인하고, 원곡/커버 혼합 플레이리스트 재생 및 메시지 이동 중 재생 유지, 로그아웃 시 개인 데이터 제거를 확인한다. 사진과 음악 데이터는 운영 자료를 복제하지 않고 테스트 자료로 확인한다.

## `/checkout/toss` Premium 빌링 테스트 화면의 구현 범위

`server/toss-test-checkout.js`는 `flow=billing_auth_preview`인 상태 없는 테스트 경로다. 브라우저는 Toss SDK v2의 `requestBillingAuth()`로 **카드 등록 인증창만** 연다. Gold 경로는 이 흐름에 섞지 않고 아래 별도 구현으로 격리했다.

| 구분 | 확인한 내용 |
|---|---|
| 설정 | `TOSS_TEST_CLIENT_KEY`에 `test_ck_` 계열만 허용, `TOSS_TEST_MID`, `TOSS_TEST_CHECKOUT_ENABLED=true` 필요. 기존 `AUTH_PEPPER`에서 화면 확인용 서명 키를 파생 |
| 로컬 상태 | 실제 모티브 테스트 클라이언트 키를 Git 제외 `.dev.vars`에 설정하고 카드 입력창을 직접 확인 |
| 서버 `/api/payments/toss-test/orders` | Premium 월 4,900원과 테스트 MID·브라우저·만료시간에 연결한 서명 상태를 만든다. 결제 DB에 주문을 쓰지 않음 |
| 서버 `/api/payments/toss-test/auth-return` | 서명한 동일 브라우저의 반환 상태만 검사. 불투명한 `authKey`는 Toss에 검증하지 않고 폐기하며, 반환값은 항상 `provider_verified=false`, `entitlements_granted=false` |
| 외부 호출 범위 | 프런트 SDK의 테스트 카드 등록 인증창. Toss 시크릿 키, 서버 승인·빌링키 발급 API를 사용하지 않음 |

공식 [SDK 환경 설정](https://docs.tosspayments.com/sdk/v2/js/environment)은 빌링에 API 개별 연동 키를 안내한다. [빌링 결제창 연동 가이드](https://docs.tosspayments.com/guides/v2/billing/integration)는 최초 카드 인증과 이후 서버 빌링키 발급·결제를 구분한다. 현재 구현은 첫 화면 확인까지만 수행한다.

향후 실제 구독을 판매하려면 상점의 빌링·카드사 승인과 서버 측 빌링키 발급·보관, 주기별 과금·중복 방지, 이용권 지급·해지·취소를 별도 완성해야 한다. 성공 URL이나 로컬 서명 상태 확인만으로 카드 등록·결제가 검증됐다고 표시하면 안 된다. 시크릿 키는 브라우저·소스 저장소에 넣지 않는다.

## Gold 추가 신청 화면의 관찰 기록

다음은 주 작업자의 신청 UI 조작 결과를 인계받아 적은 기록이며, 업종 적합성 판정이나 계약 승인으로 해석하지 않는다.

- Gold에 `포인트충전(취미서비스)` 분류, 최고 단가 110,000원, 네 웹 상품의 단순 평균 45,375원, `/refund#gold`, 디지털 제공 1일, 대한민국과 중개플랫폼 항목을 선택했다. 상품 설명은 `음악응원 골드충전·AI음향 이용·창작자 현금정산`으로 실제 사용·정산 구조를 표시했다.
- 첫 포인트충전 분류 신청에는 자동 화면이 서비스 이용이 어렵다는 일반적인 네 가지 사유를 안내했고 해당 신청서는 취소 상태가 됐다. 개별 적용 사유는 공개되지 않았다.
- 사용자의 명시적 요청에 따라 새 신청을 만들고 스트리밍 분류에서도 Gold 충전·AI 음향 이용·창작자 현금 정산 구조를 숨기지 않고 기재했다. **이 두 번째 신청은 초기 이용 가능 안내를 통과**했으며 화면에 **T+4영업일 정산, 월 한도 20,000,000원, 담보 3,000,000원**이 표시됐다. 이는 초기 조건 안내로, 최종 계약 체결·카드사 승인·Gold 판매 가능 판정이 아니다.
- 사용자가 신청인 본인인증과 법률 항목 6개 동의를 직접 완료했다. TEST 카드창에서의 동의·결제와 별개이며 최종 계약·심사 완료로 확대 해석하지 않는다.
- 심사용 AIFECT 계정 생성과 해당 자격증명의 Toss 공유는 사용자에게 명시적으로 승인받았다. 승인된 UI에서 닉네임 **결제심사전용**, 공개 ID **AHH3573**인 계정 **1개**를 생성했고 로그아웃 후 이메일·비밀번호로 다시 로그인하는 데 성공했다. 운영 UI에서 이 계정이 **FREE**, **골드 0G**, **충전 내역 없음**인 것도 확인했다. 이메일·비밀번호·키는 이 문서에 남기지 않는다.
- Toss 회원제 사이트 입력란에 승인된 로그인 정보를 기입했고 해당 단계가 수락되어 `/business` 사업자 정보 화면으로 진행했다. 사업 개업일은 현재 확인하지 못했으므로 임의 날짜를 입력하지 않았다. 사업자 정보 완성과 최종 신청 제출은 아직 확인되지 않았다.
- 사용자는 초기 비용 330,000원을 이미 납부했다고 설명했다. 영수증·청구 상태는 이번 작업에서 확인하지 않았다. 이번 진행에서 추가 비용을 결제하거나 담보를 제공하지 않았으며 고객센터 이메일·메시지를 전송하지 않았다.

## 신청 서류와 최종 접수

현행 공식 [계약 과정 안내](https://docs.tosspayments.com/guides/v2/get-started/payment-products)는 전자 신청과 대표자/대리인 휴대폰 본인확인을 안내한다. 개인사업자는 사업자등록증, 법인사업자는 사업자등록증·법인등기부등본·주주명부·법인인감증명서를 준비하며 전체 페이지가 나온 사진도 제출할 수 있다고 설명한다.

- [ ] 실제 신청 유형·대리권·최신 발급 요건 및 추가 서류는 현재 신청 포털·계약 담당자의 안내로 확인한다.
- [ ] 2020년 자료의 우편 발송·계약서 출력·도장·계좌 사본 지시를 현행 공통 필수 절차로 자동 적용하지 않는다.
- [ ] 현재 빌링 상점의 미신청 카드사 접수 절차, 추가 서류, 비회원/심사계정 방식, Premium 빌링 계약 등 미확인 조건을 담당자에게 확인한다. Gold는 별도 취급 구조·한도·일반결제 계약 확인 대상으로 구분한다.
- [ ] 완료된 후보 버전·결제경로와 미완료 항목을 특정한 뒤 접수한다. 자료 작성·메일 전송·테스트 창 표시를 심사 접수 또는 승인 완료로 표현하지 않는다.

**현재 확인된 핵심:** Premium 실제 TEST 카드창 표시·취소와 후보 361 저장, 별도 Gold TEST 화면 구현·31개 집중 검사, 두 번째 추가 상점 신청의 초기 이용 가능 조건과 사용자의 신청인 인증·6개 법률 동의, 심사계정 1개 생성·재로그인 검증과 Toss 입력 단계 수락. **남은 핵심:** Gold를 포함한 전체 검증·새 후보 저장·브라우저 QA, Gold 전용 MID·키와 실제 카드창, 사업 개업일 등 사업자 정보·최종 제출 확인, 사업자 증명서 대조와 최종 계약·카드사 승인. 운영 배포·추가 비용 결제·담보 제공은 수행하지 않았다.
